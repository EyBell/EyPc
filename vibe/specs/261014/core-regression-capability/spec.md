## 统一设计

1. 在现有 verification-map 旁保留一个机器映射：稳定 guard id、现行需求引用、语义owner及消费者路径、实际检查入口、负向验证与证据边界。登记失效、路径缺失或核心变更未映射均报错。
2. 单一正常验证入口读取 staged/unstaged/untracked 或指定 base 的差异，包含删除和重命名前后路径。输出选择原因与需求入口，运行有界检查并报告实际结果。选择器/映射本身变化要验证自身及登记核心；不以全库测试填补未知映射。
3. PR/push工作流调用同一入口；只读仓库权限，不执行真实供应方探针、账号操作或部署。工作流文件落地不等于远端已启用，更不等于分支保护已设为required。
4. 核心状态门禁由manifest逐来源运行；门禁预期来自需求，独立于普通Vitest断言。守卫自身需有能拒绝已知坏实现的canary。
5. 上游探测分开记录安装产物身份/摘要、契约结构和运行证据。版本/构建变化仅触发复核；新增可选字段、required删除/类型变更、未知布局和提取器变化分别报告。没有可识别契约时返回unknown/partial，不能从版本号、文件名或关键词推断能力消失。
6. 静态探测仅读明确的程序文件、安装元数据或显式提供的脱敏结构；不启动应用/供应方CLI、不读用户会话/凭据、不导入执行供应方代码。候选差异经维护者确认、新增fixture/负例、定向回归与必要宿主验证后再更新支持记录，不自动修改运行能力或基线。
