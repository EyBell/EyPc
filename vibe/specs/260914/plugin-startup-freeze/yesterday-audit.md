## 归因判据

1. 后续由用户恢复测试时，先核实 trace 的 start 身份与实际安装产物一致；没有 start 文件时只能判断追踪链未验证。
2. 若独立线程持续写 main-stall，且某个同步 span 有 begin 无 end，优先定位该插件调用边界；用普通运行日志关联同 PID、时间与状态。异步 inventory/CLI 长时间 pending 但主线程 heartbeat 正常，不能判主线程卡死。
3. 稳定复现后再做相同环境、相同操作的插件屏蔽/启用对照，以及单一候选路径隔离；仅「换包后正常」或一次未复现不能确认修复。
4. 文件达到上限、超过 10 分钟、dropped 非零、进程退出、宿主禁用 Worker 都会削弱证据。无 end 也可能来自退出或丢失事件，不自动宣告根因。
5. 当前结论停在「插件代码确有新增启动工作与同步阻塞风险，现场唯一阻塞点未确认」。本轮没有再次启用插件、操作窗口、调用真实 Orca CLI、结束进程或替换安装包。
