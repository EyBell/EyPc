# RAW-188：已完成未读与置顶兜底使用互斥跳转序列

Tool: codex · Date: 2026-08-29 · Level: Standard（需求）

## 输入规范化边界

## 规范化需求

- 当前 Kernel 快照中只要存在至少一个可打开的 `unread` 分组任务，「已完成未读」入口的候选序列就只能由这些真实未读任务组成；置顶分组任务不得进入同一序列，也不得在未读轮次走完后被顺带跳转。
- 只有可打开的真实未读任务为零时，「已完成未读」入口才退化为置顶分组的快捷兜底，并继续使用列表的稳定顺序与置顶固定访问身份。
- 置顶任务自身若属于已完成未读，仍通过 `unread` 分组成为真实未读候选；置顶不改变它的状态归属。
- 置顶兜底进行中若出现真实未读，下一份 Kernel 快照必须把置顶键移出入口并裁剪已访问进度；真实未读清空后，置顶兜底从稳定首项重新开始，不恢复旧游标。
- `input` 与 `completedUnread` 各自维护一份进程内轮次顺序：一轮开始后，仍在候选中的旧实例保持相对顺序，`lastQuestionAt` 等 metadata-only 更新只允许重排公开列表，不得改变这轮下一跳。
- 新生命周期实例按当前最新顺序插到轮次队首；已经排队的快捷命令仍逐次执行，新实例在下一次执行时优先，随后恢复旧实例顺序。全部当前实例成功派发后，下一次触发才按当时最新公开顺序开始新一轮。
- 打开失败不推进轮次；候选离场、未读/置顶候选种类切换、功能失效或 Provider 配置变化会裁剪或清空相应轮次。不得新增防抖、按键合并或持久化顺序缓存。
- 快捷键、`open-attention` 命令、Snapshot 字段形状和 Controller/Renderer 路由保持不变；选择权仍只属于 V7 Kernel。

## 验收意图

- 同一快照含两个真实未读和多个置顶时，连续触发超过未读数量仍只在真实未读之间循环。
- 零真实未读时，置顶兜底按稳定顺序循环。
- 置顶兜底期间出现真实未读，下一次触发立即只走真实未读；未读清空后置顶从首项重新开始。
- 置顶且已完成未读的任务仍属于真实未读候选；不可打开任务不进入任一候选序列。
- 置顶或待输入轮次已经打开 A 后，即使下一份 Snapshot 把 C 的 `lastQuestionAt` 提到列表首位，本轮仍依次打开 B、C；下一轮才从最新的 C 开始。
- 首次打开仍在执行时，新生命周期实例可在下一次串行执行中插队，随后恢复未完成的旧轮次；每次快捷触发都对应一次选择，不得吞键或重复打开同一旧实例。
