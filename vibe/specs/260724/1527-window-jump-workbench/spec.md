## Functional Contract

### Domain state

`AppState` persists feature configuration, the search query, user-created target metadata, and ten platform-separated slot records. A target has an EyPc ID, local alias, platform, exact app identity/name, current title locator, at most four prior successfully verified titles, last native reference, favorite/pinned states, and timestamps. Existing targets migrate with an empty history; manual locator edits reset learned history. Pin is independent from favorite and slot assignment. Live native windows are never persisted; Runtime keeps a session cache (`liveWindows`, `windowListLoaded`, `windowCacheUpdatedAt`) that survives Tab switches. A complete inventory replaces that cache; a partial/current-Space inventory refreshes observed rows and retains absent rows as visibly cached. Favorites, pinned targets, and current-platform slot-bound targets remain in the projected list even when unloaded or unavailable. A target with none of those retention reasons is pruned.

### Platform bridge

The preload bridge returns a window capability record, a transient list record, activation/topmost results, and an optional macOS system-settings launch. Browser/stale-preload fallback is explicitly unsupported and never fabricates windows. Shortcut slots may open the official uTools configuration screen, but the bridge never reads or returns current host bindings.

Windows only invokes fixed PowerShell/User32 code through `execFile`: the handle must still exist, be visible, non-cloaked, titled, non-tool, root-level and the last visible active popup for its root owner (unless explicitly `WS_EX_APPWINDOW`). This keeps actionable Alt-Tab surfaces and rejects helper/native browser handles before a validated numeric HWND is restored with `ShowWindow(SW_RESTORE)` and passed to one `SetForegroundWindow` attempt. The separate Windows “页面置顶” operation uses `SetWindowPos(HWND_TOPMOST)` before that same foreground attempt. macOS unwraps the CoreFoundation array through an Objective-C object bridge, then keeps only layer-zero, positive-alpha, titled windows with a valid native number and a live regular application. For a CG reference, activation first revalidates PID/app/title identity and resolves the exact CG window against a fresh managed-display map using both supported per-window masks plus per-Space reverse corroboration. If the in-process uTools/Electron call returns no binding, a fresh bounded `osascript -l JavaScript` process repeats the same revalidation, direct lookup, managed-Space reverse scan, unique-binding rule, switch, and two-second confirmation. A current binding skips switching; one remote binding switches; multiple bindings or timeout block. When both routes have no binding, only a one-window owner may use process-frontmost; a multi-window owner blocks without desktop walking.

After a valid/current Space, the JXA activation process re-reads Core Graphics and requires one layer-zero, positive-alpha record with the same PID and CG window ID. Only that record's normalized `kCGWindowName` may prove a saved CG-title mismatch. A missing/unreadable CG title fails verification without `target-title-changed`. The process then enumerates the owner's raw AX elements and calls `_AXUIElementGetWindow` on each. One CG-ID match is required and takes precedence over title/ordinal fallback; the exact AX path does not compare `AXTitle` with the CG title. The exact element is unminimized where readable, made main, raised, and installed as the application's focused/main window around `NSRunningApplication` activation; bounded retries finish only when `AXFocusedWindow` maps back to the requested CG ID. Exact-match focus failure is blocking rather than falling through to a sibling window. WJ-16 first validates a cached Space against the current managed-display map; a unique cache hit skips direct/reverse and isolated lookup, while WJ-18's activation child still requires matching application, same-source CG title, exact AX mapping, and focused-window readback. Isolated unique bindings are imported into the same session map. Space bindings remain preload-session-only and a native miss evicts them; no CG/PID/title/Space/display binding is persisted. Aggregate identity snapshots may be reused for five minutes only as development diagnostics and are invalidated on native miss; they are never activation authority. The bridge revision is `wj18-cg-title-source`; a mismatch blocks before activation. Titles are passed only through a bounded child environment, never interpolated into shell/JXA source. macOS has no arbitrary third-party permanent-topmost claim. Missing Screen Recording/Accessibility/Automation authorization is classified for the UI.

### Runtime and routing

`eypc-windows` opens the enabled page without auto-scanning. `eypc-window-slot-1` … `eypc-window-slot-10` remain `mainHide` features that restore the current Tab and dispatch a slot action, but no slot route schedules a generic post-dispatch hide. Slot/manual “展开并前置” and manual Windows “页面置顶” share the capability/cache/one-healthy-rescan path. A stale `lastNativeRef` `not-found` causes one real-time rescan and one retry. Resolution first requires exact platform/application identity and accepts one exact current/history title. Fuzzy replacement runs only against a complete fresh inventory: it strips the already-mandatory application label from title evidence, combines stable segment, weighted token, trigram, and common-edge similarity, requires a shared non-generic anchor, and applies a stricter score plus runner-up margin when the application owns multiple windows. One strong winner may activate automatically; its title/reference/history are committed only after native success. Weak, tied, multiple, or partial-snapshot candidates never auto-commit and remain confirmation/blocking paths. Only a complete successful rescan with no exact or plausible rebind candidate clears the stale reference and emits accepted `target-closed`; a partial rescan retains both the reference and cached list row and emits blocking `refresh-incomplete`. Bridge mismatch, Space unbound/ambiguity/switch timeout, title rebind, feature disablement, missing assignment, capability/permission/read failure, rescan failure/supersession/incompleteness, ambiguity, focus refusal, host call failure, workbench-show failure, unsupported topmost, topmost failure, and successful-operation silent-hide failure are all blocking diagnostics.

When `import.meta.env.DEV === true`, Runtime creates an in-memory `WindowOperationDebugRecord` for each activation/topmost attempt. The user-authorized selected target title appears at the start of that development-only trace; native bridge data remains limited to bounded `{ stage, outcome, detail }` values. Separate `pre-initial` and `pre-retry` snapshots expose only revision and aggregate counts/binding state. The trace is capped at 50 records, separately clearable, validated again at the Runtime boundary, and absent from `AppState`/storage. A non-development build creates no record, omits the environment request, and exposes no trace UI.

### UI

The `windows` feature owns a compact toolbar (search + manual load + short cache/platform meta), a single-line status/exception band, and a list-first workbench. Stable slots `1–10` live in a left collapsible vertical rail (equal-height rows, fixed 11px label with ellipsis, full text via operation tooltip); an empty slot opens an anchored picker over current rows, while an assigned slot still focuses its target (Shift clears, context menu configures the uTools hotkey). Activation diagnostics and the development-only operation-trace panel live in a right collapsible log rail (default collapsed; blocking diagnostics auto-expand the rail) so they never steal vertical space from the window list. The workbench keeps `listbox`/`option` row projection and an accessible right action layer. Diagnostics remain session-only without title, application, PID, handle, native-reference, or raw host-error disclosure: blocking entries use `role="alert"`, accepted `target-closed` uses `role="status"`, stable codes remain visible, and `windows.activation.diagnostics.clear` clears only Runtime memory. In a development build only, a `role="status"` operation-trace panel starts with the user-authorized selected target title and shows time, entry, platform, operation, result, stable code, and sanitized stage/outcome chips; `windows.operation.traces.clear` clears it. Keyboard contract: `ArrowUp`/`ArrowDown` move the list, `ArrowRight`/`Ctrl+ArrowRight` open the action layer, and `Ctrl+1`…`Ctrl+9`/`Ctrl+0` assign the focused row to slots `1–10`. The action layer distinguishes “展开并前置”, Windows “页面置顶”, and EyPc-local “列表置顶”; macOS keeps the page-topmost control unavailable with an explicit boundary explanation. Pinned rows come first; all remaining saved/live rows sort globally by application name, display name, title, then stable row ID. Favorite and stable-slot retention remain independent from ordering; assignment creates a non-favorite target unless the target was already explicitly favorited. The active row uses `aria-selected` and the search box uses `aria-activedescendant` without stealing native text handling. An explicit toolbar/`Ctrl+R` load or refresh clears the page search before enumerating so a stale query cannot make a fresh inventory look incomplete; internal cache-miss and lifecycle refreshes preserve the query. `ArrowUp/ArrowDown`, `Enter`, arrows, `Tab`, `F2` variants, save/cancel, selection, favorite, list pin, topmost, and refresh commands resolve through named runtime/keybinding layers; ordinary editing remains native.

## Out of Scope

- Hardware-specific APIs, private uTools host APIs, app/window-title writes, simulated input, and automatic global-hotkey registration.
- Background reconciliation, launch/reopen of a closed application, macOS HWND emulation/permanent-third-party-topmost, and focus workaround techniques.

## Rollback

Disable the feature in EyPc settings. Existing local target and slot metadata remains inert; removing the feature code later does not require any external state restoration.
