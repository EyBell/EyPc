# Window Jump Workbench — Handoff

## Delivery State

`wj19-native-instance-id / WJ-19.3 implemented; verification-pending` — native instance identity owns automatic matching; titles are recognition metadata only, and replacement remains an explicit confirm/cancel flow across empty, partial and replacement refreshes. The flow now has one domain state machine, one Runtime effect adapter and one action-availability policy. WJ-17 automatic title recovery and WJ-18 title equality remain superseded. Status: **实现与既有测试契约已更新；测试、类型、构建、uTools 重载和真实跳转均未执行**.

## Delivered Surface

- Domain/state: `WindowTarget.id` is the logical EyPc target; `lastInstanceId` is the last verified OS instance and `lastKnownTitle` is display-only. Legacy locator migrates to the latter and history is discarded. See [windows.ts](../../../../src/domain/windows.ts#L1) and [state.ts](../../../../src/domain/state.ts#L1).
- Native bridge: Windows verifies actionable HWND + owner/app and returns the current locator `win32:PID:HWND` without promising survival across system handle reuse. macOS requires PID + CGWindowID, force-validates identity before any Space cache switch, keys that cache by full instance, and finishes through one raw AX mapping plus exact focused-window readback. AX fallback enumeration drops rows without a CG ID; title/ordinal activation and close fallback is removed. See [preload/index.js](../../../../preload/index.js#L1), [public/preload.js](../../../../public/preload.js#L1), and [eypcPlatform.ts](../../../../src/platform/eypcPlatform.ts#L1).
- Runtime/UI: all identity paths use `instanceId`. [windowRebind.ts](../../../../src/domain/windowRebind.ts#L1) alone decides candidate lifecycle/membership and emits focus/stale-binding effects; [appRuntime.ts](../../../../src/runtime/appRuntime.ts#L1) owns one state value and one `always / browse / rebind` action policy; [WindowsPage.vue](../../../../src/pages/WindowsPage.vue#L1) reads one projection. After one complete refresh a missing instance exposes every same-app candidate for manual confirmation, including one candidate. Complete/partial refresh, Enter and Escape behavior is unchanged, but no longer duplicated across Runtime branches. If an unsaved window editor meets asynchronous slot recovery, Runtime preserves the draft and explicitly blocks rebind so the editor and candidate layers cannot coexist. The editor title remains read-only.
- Verification: existing contracts were updated but not executed. Only read-only source searches, diff inspection and preload byte comparison were used; see [verify.md](verify.md#L1).

## User Validation Focus

Reload the non-hot-reloading preload and confirm `bridge=wj19-native-instance-id`. Bind one browser window, switch its Tab/title and confirm the same target/slot remains valid. Close the original instance: a sole same-app window must still stop for explicit confirmation; the list must show that window's live title/state without inherited favorite/pin/slot badges and the guidance must retain alias + previous-title context. Space/right-click/action shortcuts must not leave the confirm flow. Exercise complete-empty → partial-new → partial-empty → complete-replacement refreshes: the flow must remain visible, the stale binding clears only on complete-empty, the partial candidate remains visibly cached, and a returned/replacement candidate receives focus. One Escape must restore focus to the original target row, while Enter plus verified native activation must atomically adopt the candidate. Equal-title sibling instances must never auto-match.
