# EyPc Product Requirements

Tool: codex

Requirement version: `2026-07-22.8`

## Purpose

This file is the current product requirement index for EyPc. Task-level history remains in dated folders under [PROJECT_STATUS.md](PROJECT_STATUS.md#L1); MQTT implementation mapping is maintained in [2606231645-eypc-mqtt-websocket-tab/06-sync-doc.md](2606231645-eypc-mqtt-websocket-tab/06-sync-doc.md#L1).

## Global

- EyPc is a keyboard-first uTools plugin for local PC operations.
- Runtime actions are the only user-visible mutation boundary; UI components emit commands and never perform shell, storage, MQTT, or filesystem writes directly.
- Top-level feature switching uses configurable `Ctrl+Shift+数字`; Settings opens with `Ctrl+Alt+S`; `Shift+Escape` hides the plugin window.
- Shortcut resolution is layered by command context. Editor, drawer, preview, dropdown, and popover layers take priority over page-level shortcuts.
- Host-shell transient command layers must be represented in runtime state before DOM focus is trusted, especially when a host reserves browser-like shortcuts.

## Shared Interaction Surfaces

Current increment authorities: [260713/0834-cross-tab-responsive-command-panels/spec.md](260713/0834-cross-tab-responsive-command-panels/spec.md#L1) and [260718/0947-quick-jump-center-overlay/spec.md](260718/0947-quick-jump-center-overlay/spec.md#L1).

- Operation controls use one product Tooltip owner with hover/focus activation, accessible name, current shortcut or disabled reason, viewport clamping and `aria-describedby`; native `title` is not the only help surface. Buttons, menu/tab/option/treeitem roles, draggable rows, checkbox/radio/number/range controls and selects are covered, while Quick Jump temporarily suspends the Tooltip layer.
- `Ctrl/Cmd+ArrowLeft` opens or switches to target detail and `Ctrl/Cmd+ArrowRight` opens or switches to target actions across Ports, full/Quick Favorites, MQTT row targets and Settings command rows. Explicit action arguments outrank an already-open frozen target; invalid explicit targets fail instead of silently falling back.
- A focused Port outside the current visible selection becomes the single target; a focus that remains inside the selected batch preserves the batch action target.
- Ordinary text editors keep native arrow/navigation ownership. Settings only claims left/right panel commands from non-editing command rows, and Quick Favorites exposes safe read-only details/actions only.
- Opening a context panel moves focus into it; switching sides refocuses the new panel; closing restores the trigger or the stable list/grid owner. Buttons, context menus and shortcuts dispatch the same action id.
- Tab content owns page height. Wide pages dock side panels; `721–1100px` temporarily reduce secondary rails; `<=720px` panels become exclusive inside the active Tab. Every main page supports vertical scrolling and must not require page-level horizontal scrolling at 420px.
- Global Quick Jump renders each compact solid badge at the exact center of its target rectangle in a fixed pointer-transparent top layer. Marker width may grow for multi-character labels, but its center never shifts for title anchors, collisions or viewport edges; overlap and partial edge clipping are accepted so target correspondence remains deterministic.

## Ports

- The port page scans local TCP listeners, dedupes by `pid:port:protocol`, supports search, user-defined groups/folders, focus movement, group filtering, detail drawers, action drawers, and safe kill/force-kill commands.
- Metadata changes to port groups/folders are plugin-state changes only. Process kill actions must revalidate current PID/port ownership.
- Port group editing follows command-soul semantics: `F2` edit, `Shift+F2` rename, `Ctrl+F2` move folder, `Ctrl+S` / `Ctrl+Enter` save, `Escape` cancel, and editor-local `Tab` field cycling.

## File Favorites

Current increment authority: [260711/1452-file-favorites-workbench/spec.md](260711/1452-file-favorites-workbench/spec.md#L1); implementation traceability: [260711/1452-file-favorites-workbench/requirements-traceability.md](260711/1452-file-favorites-workbench/requirements-traceability.md#L1).

- Favorites are plugin metadata for file/folder paths and virtual groups. Removing a favorite never deletes the disk file or folder.
- Quick favorite mode is search/open/reveal/copy only; management mode supports add, edit, move, duplicate focus, and directory listing.
- Open/reveal/copy stays behind the platform bridge in [src/platform/eypcPlatform.ts](../../src/platform/eypcPlatform.ts#L1) and [preload/index.js](../../preload/index.js#L1).
- Favorite metadata normalizes duplicate ids, orphan/self/cyclic parents, and equivalent paths without rewriting the displayed path. Windows drive and UNC paths compare case-insensitively with normalized separators; POSIX paths remain case-sensitive.
- File action results distinguish confirmed success, host dispatch, reveal-as-open fallback, and failure. Missing, offline, or denied paths remain saved and surface runtime health instead of being silently removed.
- Full favorites use command-owned `containers`, `items`, and one-level `directory` targets with deterministic focus, selection, drawer targeting, `Escape` recovery, inline rename, batch metadata actions, and one-step metadata-removal undo.
- Full favorites keep a compact two-pane layout, collapse containers into a command-controlled side layer below 720px, and provide keyboard, focus, ARIA, loading, empty, error, unsupported, and 420px overflow-safe states. Quick favorites remain readonly and never inherit management-page selection or drawers.
- File favorites never create, move, rename, or delete real files; directory reads are non-recursive and do not follow symbolic links.

## MQTT

- MQTT over WebSocket is a first-class feature with lazy page/runtime loading, dynamic MQTT client import, SQLite-first local archive, legacy archive fallback, and local-only persistent secret storage.
- Connection configs store endpoint, Client ID, username, subscriptions, aliases, colors, publish defaults, reconnect options, `syncRecords`, and layout preferences. Password/token values persist only in the preload local userData encrypted secret envelope `mqtt-secrets-local.json`; they never enter app state, archive, templates, SQLite mirrors, or synced storage.
- `MqttConnectionConfig.publishTopics` stores multiple default publish topic candidates. The first normalized value is mirrored to `publishTopic` for compatibility with the existing send editor.
- Subscription topics are configured per connection. Aliases/colors are pruned with topic removal, and topic colors normalize to five defaults or valid hex colors.
- Runtime owns message sessions, publish templates, outgoing history, publish draft history, record-list focus/selection, drawers, preview, search, layout, view preferences, and focus targets.
- `MqttState.viewPrefs` persists the last `全/收/发/藏` information filter and valid topic filters per connection config.
- MQTT ordinary message rows and outgoing history rows sort newest first by message `timestamp`. Publish draft history sorts newest first by `updatedAt`. Publish favorites/templates sort newest first by `MqttPublishTemplate.operatedAt`, with `updatedAt` / `createdAt` fallback for older archives.
- `MqttArchiveState.publishDraftHistory` stores overwritten drafts and manual saves only. Real sends remain ordinary outgoing message records and are not duplicated into draft history.
- MQTT focus targets include `records`, `topic-filter`, `publish-topic`, `publish-payload`, `publish-options`, `publish-history`, draft-history editor fields, `connections`, and `subscriptions`.
- Connection rail rows support focus highlight, hover highlight, multi-select, `ArrowUp` / `ArrowDown` movement, `Space` selection, `Ctrl+C` endpoint copy, delete shortcuts, row-local edit/detail/more buttons, and right-click action menus.
- Subscription rail rows support focus highlight, hover highlight, multi-select, `ArrowUp` / `ArrowDown` movement, `Space` selection, `Enter` topic filter, `Ctrl+C` topic copy, `Ctrl+Enter` use-as-publish-topic, delete shortcuts, row-local edit/detail/more buttons, and right-click action menus.
- `Ctrl+ArrowLeft` opens the detail drawer and `Ctrl+ArrowRight` opens the action drawer for MQTT record, connection, subscription, and draft-history row targets.
- `Ctrl+S` favorites/unfavorites the current record/template in record focus and saves the current publish topic/payload as a template in publish editor focus. Edit layers keep `Ctrl+S` as save.
- `Ctrl+1/2/3` select `全/收/发`; `Ctrl+M` selects `藏`; `Ctrl+H` opens/closes the send-area draft-history popover and focuses it; `Ctrl+Shift+H` manually saves the current draft. `Ctrl+L`, `Ctrl+Shift+L`, and `Ctrl+Shift+M` have no default MQTT binding.
- `Ctrl+Shift+S` toggles layout, `Ctrl+Shift+F` opens the topic dropdown, and `Ctrl+P` enters the publish topic field. Publish topic/payload editors keep native `Ctrl/Cmd+ArrowLeft/Right`; QoS/retain options open from their explicit button.
- Draft-history rows apply only from the row apply button or `Enter`; plain row click focuses the row. `Ctrl+Enter` applies and sends the focused draft while keeping the popover open.
- Draft-history focus owns `Space` multi-select, `Ctrl+Left` detail, `Ctrl+Right` actions, `F2` title/note edit, `Shift+F2` topic/payload edit, `Ctrl+Delete` / `Ctrl+Backspace` delete, and `Escape` close/cancel.
- Draft-history editor modes use `Ctrl+S` / `Ctrl+Enter` save, `Tab` / `Shift+Tab` field cycling, and `Escape` cancel.
- Publish topic/payload focus clears information-list focus so `Space` cannot keep toggling message selection while the user edits publish content.
- Topic dropdown lists only current connection subscriptions, supports alias/topic search, is single-select, and filters only ordinary message rows under `全/收/发`; template and history rows ignore topic filtering.
- Subscription modal rows, connection config subscription rows, and connection config publish-topic rows use `ArrowUp` / `ArrowDown` for same-field row movement and `Ctrl+Delete` / `Ctrl+Backspace` for current-row deletion. Plain `Delete` / `Backspace` inside text inputs remains native text editing.
- Connection config editor `Tab` / `Shift+Tab` cycles through connection fields, each subscription alias/topic/color row, each publish-topic row, connection option fields, and storage options inside the editor layer.
- Pure Shift preview can open a readonly overlay for valid MQTT message/template rows and draft-history rows while the draft popover is open. `Ctrl/Command+Shift` suppresses Shift preview so `c-s-*` commands remain shortcut-owned.
- MQTT UI uses compact rails, red/green/gray status rectangles, connection-title `host:port` hover text, a top topic dropdown without a `topic:` prefix, unified record/favorite/history rows, a send-area draft-history popover, a draft editor modal, and a publish options popover.
- MQTT local popovers for topic filtering, publish options, and draft history must be topmost inside the workbench in both stack and split layouts, but must stay below global detail/action drawer masks, previews, modals, and shortcut top-layer hints.

## Codex Companion

Current increment authority and detailed requirement/implementation map: [260718/1148-codex-quota-float/spec.md](260718/1148-codex-quota-float/spec.md#current-requirement-and-implementation-map).

- Codex is an independently configurable feature Tab. General Settings controls feature enablement; the Codex Tab owns the 1–365 day rolling window (default 30), companion visibility, appearance, readiness and shortcut configuration.
- The companion uses a real uTools child window and retains water-ball/compact-card skins, host-owned resize, automatic collapse and macOS all-Spaces behavior. In the expanded surface the six task Tabs are the first content; the old water/card, hidden, refresh, settings and close toolbar does not render there. Card appearance stores an explicit surface/foreground pair rather than forcing paper-white.
- Card surface and text/icon foreground are edited in one modal with two simultaneous saturation/lightness boards, hue/HEX synchronization and a visibly muted invalid-contrast gamut. Selecting either board keeps that color and moves the partner to its nearest readable lightness. The current-color swatch opens an in-place keyboard-accessible set of alternate color cards. Valid drafts preview on the real desktop companion without persistence; confirm saves the pair once, while cancel/Escape/backdrop/unmount restores the last saved style and colors. The floating child displays the result only and never contains water/color editing controls.
- The compact water ball has no intermediate mini-detail. Its upper half is a counter-safe zone and does not expand on hover; the three counters stay directly clickable and show child-owned opaque purpose help after 200ms hover/focus without expanding or switching tabs. Entering the lower half expands immediately, while explicit ball click/keyboard activation remains available and touch never simulates hover. The center selects ordinary 5-hour positive quota, then ordinary weekly positive quota, then the highest positive Spark pool only when neither ordinary window is positive. Spark displays an `S` above the percentage and its outer ring follows the same pool's weekly window. An absent window is never fabricated or treated as zero; expanded quota text renders every returned ordinary/Spark window.
- Easy Agent is not implemented yet. The interim adapter keeps two host channels: the local Codex App Server supplies quota, models, inventory, creation and verified persistent actions; a macOS Codex Desktop private-IPC companion bridge supplies live task/read authority and archive-refresh notification. The App Server connector is therefore still required in the current phase.
- CLI startup is independently diagnosable: EyPc auto-discovers only controlled macOS/Windows candidates and may store one user-selected, validated executable location in local plugin storage. The UI exposes only safe source/availability labels, never the actual path. Without a manual location it falls back to automatic discovery plus the existing App Server connector and explicitly warns about connection delay; this fallback never turns local cache or App Server activity into Input, ongoing or completed-unread authority. Windows supports CLI discovery/validated shim handling, while the private Desktop live bridge remains a macOS canary.
- Host Snapshot V2 reads the local Codex App Server plus an allowlisted native project registry. Ordinary inventory remains strictly read-only: the main `.codex-global-state.json` is authoritative and `.bak` is used only when the main file is missing/invalid. The sole write exception is an explicitly confirmed native project removal transaction; EyPc never scans Codex SQLite or LevelDB. A Codex Desktop full snapshot may be consumed transiently inside preload for live-state projection, but its bodies/items/raw identities never cross the bridge or persist.
- Every `archived=false` page is read to completion. Project ownership uses native thread assignment first, native projectless IDs as `Chats` second, deepest active project-root cwd match third; unmatched tasks are treated as removed/unregistered and excluded. Native state is fingerprinted before and after scanning and the entire scan retries once on change.
- Each candidate must have a valid newest Turn `startedAt`; there is no `updatedAt`/recency fallback. A malformed cursor, page, project state or existing Turn without `startedAt` fails the whole scan. Controller retains an older verified snapshot as explicitly stale, or shows an error empty state when no verified snapshot exists.
- Conversation projection V3 exposes `全部 / 待输入 / 动态 / 已完成 / 已隐藏 / 项目`. The rolling-day boundary is inclusive. Source task arrays sort strictly by newest Turn `startedAt` descending then anonymous key. Each task Tab and each dynamic status segment visually places pinned tasks before unpinned tasks while preserving stable order inside both partitions; search only filters the active Tab.
- `statusAuthority=desktop-live` is the only authority for `waiting-input / waiting-approval / active`. When the Desktop bridge is connecting, not running, incompatible or failed, App Server state, local cache and recency heuristics cannot produce Input/active; the row immediately appears under `宿主状态未知` and is excluded from those counters. Persisted completed/failed/interrupted Turn results remain visible without pretending to be live.
- `全部` contains every in-window unarchived task and marks locally hidden rows. `待输入` contains every desktop-live waiting-input task, including locally hidden rows. `动态` internally orders `待输入 → 正在进行中 → 需关注 → 宿主状态未知 → 已完成未读`. `已隐藏` preserves actual state. `已完成` contains non-hidden, non-active rows whose newest Turn completed.
- The project Tab mirrors native `Pinned / Projects / Chats`: native pinned conversations/projects first, then clearly marked EyPc local pins; remaining native projects follow project order and include empty projects; Chats contains only native projectless tasks. No task appears twice. A project-name search match shows all its in-window tasks, otherwise only matching tasks remain.
- Task and project aliases are display/search metadata only; a list row shows the alias when present and otherwise the original name, never a placeholder caused by a missing display field. The original name remains searchable and appears in detail/Shift preview when an alias exists. Original identity still governs ownership and archive. Native order is read-only. EyPc local pins can be reordered with `Alt+↑/↓`; task pins immediately move the row into the pinned partition of the current task/status view, while project pins enter `Pinned`. Pin source is expressed by the fixed `顶` control and its 200ms help, never by row-tail “本地顶” text: local uses warning color, native/Chats remain focusable with `aria-disabled` and every input route shares the read-only gate. Project-page `隐/显` is reversible local grouping visibility and never removes its tasks from other Tabs or counts. Project `移` is a fail-closed native Codex sidebar-removal transaction and never deletes the directory, assignments or conversations.
- First use defaults to `动态` while retaining `ongoing` as its stable persisted ID. Last Tab, project collapse, aliases, local pin order, local project-hide set, time window and display geometry persist. Legacy local-remove sets are discarded on migration without changing Codex. Search, selection, focus and confirmation do not persist. Storage uses hashed task keys and stable project fingerprints; raw IDs, paths, action aliases and task lists remain memory-only.
- Task rows keep fixed `顶 / 隐（显）/ 归（确）/ +` actions; project rows keep fixed `顶 / 移（确）/ 隐（显）/ +` actions. Every action owns an opaque `24px` slot, four-slot rails are `105px`, and disabled actions retain their slot. Expanded information uses a `12/10/9px` hierarchy and task/project rows have a `40px` minimum height. `+` opens the new-thread composer for the real project.
- The Codex floating child does not mount the main product Tooltip layer and never uses native `title`. The compact quota surface has no explanatory bubble. Privacy-safe task detail appears in an opaque card after 500ms, while task status and short-character action explanations use a child-owned opaque hint after 200ms. Full action access remains available through the drawer, pure-Shift preview, ARIA and Quick Jump; other main-app surfaces continue using the shared Tooltip owner.
- Destructive operations require same-position confirmation within five seconds. With no active selection, the task core opens Codex, Ctrl/Cmd+core selects without opening, and the 38px full-height left rectangle starts selection. Once any task is selected, both core and left clicks toggle membership; removing the last member exits selection mode. Selection mode always shows its label/count/Esc hint, de-emphasizes unselected rows and gives selected rows an accent/running/pending theme gradient with stronger hover/focus/active. The left rectangle always retains the task-state icon and synchronizes `aria-pressed`. Task rows, left buttons and right action buttons own Space/Enter separately so a child action runs once without changing selection. Search/Tab/refresh removes invisible selections.
- Two or more visible selections automatically show an absolute `已选 N / 归 / 操 / 清` toolbar. It anchors at the opposite top/bottom edge from the focused or last-selected row and recomputes on selection, focus, scroll and resize without changing task DOM order, row coordinates or list height.
- One item is highlighted per Tab. Arrow movement temporarily owns highlight until the pointer actually moves again. Right-clicking an unselected task first makes it the sole selection; right-clicking a selected task preserves multi-selection, while a project target clears task selection. Right-click and Ctrl+right then open the same full action drawer; its arrows move among actions and Enter/Ctrl+1…9 execute. Batch actions never expose operations that lack batch semantics.
- The isolated Codex shortcut domain adds settings-visible, rebindable `codex.thread.createFocused` on `Ctrl+T` (displayed as `c-t`) and continues to own arrows, Space, Enter, Ctrl+left/right, Delete, F2, Ctrl+P, Alt+up/down, Ctrl+F/R, Ctrl+1…9, F/Shift+F Quick Jump and Escape. Conflicts are reported only when Tab, layer and `when` can be true together. The child resolves the effective bindings with the same `when`/layer precedence while locally owning DOM focus, `codex-composer` input role and transient layers.
- Pure Shift opens a non-focus-stealing task preview: hovered task wins, otherwise the keyboard-highlighted task is used. Shift+up/down moves highlight and preview without changing selection; actual mouse movement restores hover ownership. Ctrl/Cmd/Alt+Shift, editable focus, composer, confirmation, drawer/detail, Quick Jump and model layers suppress it. The preview contains only name/original name, project, state/active flags, creation/first/latest/completion times, duration, source, hidden/pinned and archive capability; it never reads body, summary, raw ID, cwd or path.
- Escape unwinds confirmation → composer/model → Quick Jump → Shift preview → inline edit → detail → more actions → multi-selection → search → collapse. A single-item detail always returns to the same target's more-actions drawer and focuses “查看详情”; the next Escape closes to the original row. Ctrl+left/right layer switches retain that original trigger. Batch drawers have no detail child and close in one step. Missing targets/triggers fall back to a visible task or the list container. Shift preview closes on key release, window blur, collapse, Tab switch or another layer; an Escape-closed preview stays suppressed until Shift is released.
- Quick Jump excludes targets covered by composer/drawer/preview/masks, clipped by an ancestor, outside the viewport, `pointer-events:none`, or absent from the hit stack. Opening it closes Shift preview. Row markers transfer the single highlight; fixed action markers execute the corresponding row action through the same confirmation and availability gates. Normal badges use dark opaque backgrounds with bold white text and white outlines; the active target uses yellow with dark text and outline.
- Every new-thread entry opens a composer showing target project, frozen current model name/ID, selection reason and corresponding quota. The native multiline field autofocuses and supports system dictation; Enter inserts a newline, Ctrl/Cmd+Enter submits, Tab/Shift+Tab stay inside, and Escape cancels/clears/restores focus. Users may send-and-open or create an empty thread; a changed quota/catalog/project fingerprint refreshes the explanation and requires a second confirmation.
- The default model policy is `quota-auto`: ordinary quota uses configured `newThreadPreferredModel`, otherwise the catalog default/first non-Spark model; any actually returned ordinary window at zero selects the highest available Spark pool/model, while a missing window is not zero. If Spark should be used but its model/quota is unavailable, manual selection is required. A composer override affects only that thread.
- The dedicated transient bridge calls `thread/start` with exact cwd/model and `allowProviderModelFallback=false`, validates the response's top-level actual model/cwd, then optionally calls `turn/start` and opens a thread-only Deep Link. First-turn failure cleans the zero-turn thread and retains only the in-memory draft; uncertain cleanup disables automatic retry. A started turn survives Deep Link failure and receives only a short-lived reopen alias. App Server unavailability never copies or encodes the prompt and only offers an explicit blank-Codex action.
- The Desktop bridge consumes versioned initialize, thread snapshot/patch/follow, request and read-state events through a secure loopback Unix socket. Socket owner/mode and protocol versions fail closed. Its ordinary watchdog runs every 5s and temporarily backs off to 1s after three consecutive failures; Activity Delta V1 remains connector-only compatibility and cannot create live state.
- Completed-unread requires both a completed newest Turn and Codex-owned `hasUnreadTurn`. Live read-state wins; when the desktop is disconnected, Codex's own persisted unread set may be used as `desktop-persisted`. EyPc open, hide and restore never acknowledge or clear unread, and local receipts never become unread authority. The compact surface counts only authoritative waiting-input, current-active and completed-unread, capped at `99+`.
- A thread reported `active` by the connected Desktop bridge blocks archive. Single archive accepts only a short-lived action alias plus expected version/latest-Turn/source fingerprint, rereads identity/state/recency/Turn/native fingerprint, rejects active/inProgress/change, archives, then verifies absence from `archived=false` and presence in `archived=true`. After verification it dispatches versioned `thread-archived` to the connected Codex Desktop so its sidebar can refresh without restart; dispatch failure is reported but does not roll back verified persistence. Failure before verification never optimistically removes a row.
- Project “全部归档” ignores the display window and rescans all unarchived history for that project. It skips active rows and processes 20 per batch at concurrency two with per-task dual verification; partial failures remain visible with individual results. Real project-batch mutation requires separate temporary-project authorization.
- Three appearance presets and validated custom theme/water settings remain available. Card surface and foreground are edited together in one modal transaction with always-visible H/S/L and six-digit HEX controls; invalid HEX remains a local draft and real companion state changes only after one atomic confirmation. Card text/icon contrast must reach `4.5:1`, derived focus/boundary contrast `3:1`; deep and light cards are both allowed while the water surface retains its dark constraint. Reduced motion removes wave movement.
- Renderer-facing snapshots/actions never include raw thread/Turn IDs, paths, cursors, Turn items, account/session IDs, tokens, native state objects or transcript content. Desktop full snapshots are transient preload input only and are reduced to anonymous live/unread authority before crossing the port. New-thread requests carry only a hashed project key, short-lived project alias, project/context fingerprints, model ID and transient prompt. The prompt never enters general actions, snapshots, logs, storage, process documents, error memory, Deep Links or clipboard and is cleared after success/cancel/close; raw identity/path mapping exists only in preload memory.
- Codex startup must not depend on a GUI host inheriting shell/NVM PATH. Controlled JavaScript CLI wrappers use their verified sibling Node runtime; startup failures expose only a bounded error code/message and never raw stderr, command paths or environment values.
- When the Codex feature is enabled, first app launch performs a privacy-minimized macOS/Windows readiness inspection even when its Tab and float are inactive. It reports platform support, controlled CLI/runtime discovery, observational related-process state and controlled config-file metadata; if the feature starts disabled, inspection waits until enable. The configuration Tab keeps separate text guidance for runtime, process, config and App Server failures and provides a fresh reinspection action.
- Readiness diagnostics tolerate additive uTools preload version skew. If a legacy desktop preload has the Codex snapshot bridge but lacks the newer inspection method, EyPc infers only the host platform category and waits for an App Server round-trip before treating the CLI as verified. A successful read becomes authoritative availability evidence; the page must never display system/CLI “unsupported” beside loaded configuration or a connected App Server.
- Windows discovery covers controlled npm-global, local, Volta, NVM and inherited-Path candidates. A `.cmd`/`.bat` shim is never direct-spawned through a shell: it must resolve to a known Codex JavaScript entry plus a verified absolute Node runtime, or to a verified bundled native Codex binary. Environment snapshots never expose paths, PIDs, command lines, raw process output, config contents, credentials or proxy material.
- On macOS, Codex startup must also support an active local static PAC when the GUI host has no explicit proxy environment. Discovery is bounded, loopback-only and child-only: PAC code is never evaluated, proxy material never crosses into UI/storage/logs, and EyPc does not change system network settings.
- On macOS, the companion is always-on-top and visible on every ordinary and full-screen Space of its current display. The host reapplies this after creation, display migration and geometry rebuild; the Codex page shows only privacy-safe supported/enabled diagnostics. Real multi-Space interaction remains a host acceptance gate.
- One `codex.float.toggle` action owns companion visibility. Inside EyPc it defaults to `Command+Option+Q` on macOS or `Ctrl+Alt+Q` on Windows and remains available across Tabs and ordinary editors. A static `eypc-codex-toggle` uTools feature exposes the same action for system-global binding. A separate `codex.float.activate` action and `eypc-codex-activate` entry default to `Ctrl+Alt+Enter` and directly show, expand and focus the internal card for keyboard selection.
- Renderer contracts remain behind Host Snapshot V2, Conversation projection V3, Activity Delta V2 and platform-owned read/open/archive/float ports. A future Easy Agent adapter may replace both interim App Server and Desktop companion channels while keeping anonymous identities, six Tabs, local metadata and confirmation behavior stable.

## Settings

- Settings owns feature visibility/order, shortcut profiles, shortcut conflict/reservation visibility, storage status, and shared tool preview preferences.
- Shortcut edits are Settings-local drafts until saved as runtime shortcut profile updates.
- Non-editing shortcut command rows support left detail, right actions and right-click actions locally; input/select controls retain native editing behavior.
