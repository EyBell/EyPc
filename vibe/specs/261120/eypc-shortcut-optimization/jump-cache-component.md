# 快捷键管理 · 跳转缓存组件

关键词：任务跳转、统一快照、状态轮次、缓存预热、宿主落点

[快捷键管理](spec.md#L1)的第一批实施规格，2026-11-20 确认。旧任务、最新任务和新入任务共用进程状态缓存。来源事件决定任务何时可选，当前轮次决定下一次打开哪一项。[任务轮次](../../requirements/shortcut-management-raw-001.md#L1) · [来源快照](../../requirements/shortcut-management-raw-002.md#L1) · [重排和派发](../../requirements/shortcut-management-raw-003.md#L1)

## 已确认的行为

| 序号 | 使用场景 | 要求与依据 |
| --- | --- | --- |
| 1 | 上一／下一 | 从可信来源候选的最高非空层选取。顺序为进行中 → 待输入或待确认 → 已完成未读与待继续 → 已读置顶。层内跨来源按最近提问倒序。整层切换且无共同候选时从新层边界开始。隐藏、暂停、不可打开或关闭来源的任务，以及子任务，均排除。[RAW-222](../../requirements/shared-raw-222.md#L23) · [当前游标合同](../../PRODUCT_REQUIREMENTS.md#companion-多来源汇总) |
| 2 | 连按与列表重排 | 每按一次推进一格，首个立即提交派发，打开期间只保留最后一个待派发目标。短时间连续切换保持幸存项次序，同层新项追加，失格项立即退出。新来源快照就绪等列表重排发生时，接纳新的排序，默认保留仍合格的游标和专用已访问实例。游标失格时按旧次序就近承接，整层无共同候选时取新层边界。同一尾目标已成功派发且仍合格时复用该次结果，首键失败后仍合格的同目标尾键可以重新打开。[连续切换规则](../../260915/companion-cycle-priority/spec.md#L29) |
| 3 | 待输入与未读专用键 | 待输入键和角标共用轮次，新增待输入、同任务出现新的真实请求或重新进入待输入时，下次按当前顺序重走。已完成未读维护独立轮次，新完成实例优先，真实未读清空才重建置顶兜底。公开候选和新一轮按最近提问时间排序，普通元数据变化保留本轮旧项相对顺序，置顶兜底按置顶顺序，失败不消费专用轮次。[RAW-003](../../requirements/task-recovery-input-cycle-raw-003.md#L18) · [RAW-188](../../requirements/shared-raw-188.md#L24) · [8 月 29 日裁决](../../requirements/conflict-register.md#2026-08-29dec-20260829-02-attention-稳定轮次) |
| 4 | 缓存更新与恢复 | 普通显隐保留进程缓存。来源事件触发增量更新。冷启动、重连或明确成员缺口由后台恢复相应来源。可信切片可独立发布，其余来源继续预热。完全无可用缓存时结束此次触发，无等待、事后回放或缓存超时提示。已有可信来源且候选确实为空时走无候选结果。[RAW-143](../../requirements/codex-raw-143.md#L16) · [本专题 RAW-002](../../requirements/shortcut-management-raw-002.md#L1) |
| 5 | 精确任务快开 | 快速任务查看从已发布状态进入，数字、标记及已选行打开绑定当前可见根任务。同一任务经过排队或应用启动后，按当前身份和可打开性复核。通用键另查当前最高层资格，专用键另查原状态实例及轮次。快照更新后只校验原身份。[统一任务命令](../../PRODUCT_REQUIREMENTS.md#companion-多来源汇总) |
| 6 | 打开后的已读 | Codex 原生完成未读以所选任务当前完成实例的原生读态或匹配读回执清除。仅收到派发时仍保留未读。CodexHost 额外进程、Claude、Cursor 和 Orca 分别使用各自现行已读逻辑；专用轮次的访问记录独立于原生已读。[本专题 RAW-004](../../requirements/shortcut-management-raw-004.md#L1) |

## 组件职责

| 序号 | 环节 | 输入和交付 |
| --- | --- | --- |
| 1 | 后台维护 | 以启用来源为单位处理新增、移除和状态事件。合入可信任务状态、打开资格及精确目标后，原子更新该来源切片并发布同版本的任务和候选。保留仍可信的上一切片，关闭来源立刻排除。拒绝旧代际和未完成的来源切片。打开映射随成员事件更新，保存在 Host 私有内存。 |
| 2 | 快照选择 | uTools 静默入口及局部任务快捷键消费一次已发布的 V7 快照。使用其中可信部分的 `cycleKeys`、`attentionKeys` 或所选根任务。Codex 旧别名超期时仍使用有效的私有打开映射。映射缺失时结束当次请求，由同一来源代次的精确库存索引补回。选择、缺失处理及打开回执路径新增的全量任务清单读取和强制预检均为零。 |
| 3 | 派发与回执 | 选择时绑定原身份、来源代际、状态实例和适用轮次。取出排队请求、应用就绪等待结束、实际向来源派发前，核对当前资格。已经派发的原生操作按其结果记录，迟到回执只更新仍符合原请求的游标及轮次。已有目标后的应用启动、精确检查和真实派发失败继续按打开路径处理。 |

## 第一批缓存与派发验收

使用同一批次构建及真实 `host-loaded` 身份。用[脱敏诊断](../../../../scripts/probe-eypc-diagnostics-runtime.mjs#L63)关联来源事件、快照发布、选中、应用就绪、派发、窗口到达和原生读确认。分别记录来源事件到可选、选中到派发、派发到窗口到达。验收只回填匿名计数、结果和时间差。

| 序号 | 手动场景 | 观察点 |
| --- | --- | --- |
| 1 | 热态触发上一、下一、待输入、已完成未读、任务快看和选中行打开。轮流覆盖 Codex、Claude、Cursor、Orca，含 Codex 打开映射失效 | 取同一已发布版本的合格任务。入口、打开时及成功回执后，按触发原因核对新增的清单读取和强制预检均为零。映射失效时原请求结束，后台补回后须重新触发。 |
| 2 | 在来源 A 已有缓存、来源 B 首轮未完成或重连时按键。另试完全冷启动和可信空快照 | A 的合格候选可立即派发。B 就绪后参与后续选择。完全无缓存的按键当次结束，后续发布无补跳、无缓存等待或超时报错。可信空快照走既有无候选反馈。 |
| 3 | 连续正反切换，打开过程中加入同层任务、发生列表重排或出现更高层，另试单项环首键失败 | 每按推进一格，尾键落最后仍合格的目标。重排保留合格游标，失格后按旧次序寻幸存邻居或从新层边界开始。首键失败后仍合格的同目标尾键获得自己的派发机会。 |
| 4 | 普通 Codex 与 ChatGPT 项目各新建一条任务，再让既有任务收到新的真实请求。另试来源关闭及旧发布晚到 | 来源事件到入包再到候选和窗口落点可对账。任务可在按键前入包，待输入角标与快捷键共用新轮。关闭或旧代际来源的发布不能重新加入当前候选。 |
| 5 | 应用拉起期间解决所选待输入、移除通用候选或换掉精确目标。另试旧回执晚于同键再次完成或置顶兜底重建 | 实际派发前只核原任务，资格失效即结束。旧回执不消费新实例或新轮，不夺回失格游标。 |
| 6 | 让最近提问顺序与进入状态顺序相反，打开部分专用候选后重排。分别让待输入新增请求及真实未读清空 | 普通重排保仍合格的已访问实例。待输入新请求按现行规则重开，真实未读完结时按置顶顺序重建兜底。新一轮按当时应有顺序选择。 |
| 7 | 打开一个 Codex 原生已完成未读任务，分别取派发、窗口到达和原生确认。让同一任务新完成并补发旧回执，再抽查其他来源 | 只有匹配当前完成实例的原生确认清该 Codex 项，其余任务的未读保持。原生确认前可推进访问轮次。旧回执保留新完成项的未读，各来源继续用自己的清读证据。 |

### 统一审核续修

1. 成员检查成功取得的在库和已归档清单交给同代预检一次使用。成员变动只入队一次，清单被更新信号或来源换代淘汰时重新取证。V7 对同一基线的等价证据重放复用任务和视图，新的成员请求水位在重放判定前仍可独立交付。实机以库存来源、V7 包号和两端应用时间核对减少的工作量。[成员检查](../../../../preload/index.js#L8234) · [库存回放](../../../../scripts/check-companion-lifecycles.mjs#L787)
2. 专用键完成派发后，由 Kernel 按选中时的实例和轮次结算访问。Navigation 用该结果决定通用游标归属及合格同目标尾键能否复用派发。原实例晚回成功，新的待输入实例仍可访问，通用游标留在重排后仍合格的位置。热键只取当前诊断设置，近期日志不随按键复制。[实例结算](../../../../preload/companion/task-kernel.cjs#L1558) · [快捷回放](../../../../scripts/check-companion-lifecycles.mjs#L978)
3. 实际开窗路线按同版十对目标可见结果决定。显式指定应用须十次都到达精确目标，派发到可见的中位数更低且 P90 不回退。只有应用前台回执或取不到精确会话时继续使用现行深链。[配对步骤](../../261114/codex-state-sync/delivery.md#shortcut-read-reconciliation-261120)

### 完整首包下的快捷键与目标回执
