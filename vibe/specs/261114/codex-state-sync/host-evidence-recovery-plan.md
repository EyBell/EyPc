## 2. 宿主兼容的闭合证据

1. 从现有 Cursor 库存查询抽出可复用的只读 SQLite 调用。支持已存在的驱动与 `/usr/bin/sqlite3` 等平台入口。子进程按参数调用，验证路径和线程键，超时和输出上限沿现有合同。生产只查询当前库存中已确认机器身份的父子对。按批读取，独立于首包投影。真实宿主为 Electron 34.5.8 的 Node 20.19.1，构建为 Node 24.14.0。
2. 闭合、明确打开、未知分开表达。部分包和不可用读取保留同一关系和因果域内已确认的证据。完整查询无对应边时撤销其闭合资格。换父、关系移除、换域或确定的较新活动使旧证据失效。重复读到 `closed` 沿用原序列，避免旧边在新活动后重新获胜。
3. 预检首包与实时更新共用节点准入。结果晚到或机器身份晚确认时，只重新发布受影响的父任务。闭合限定于机器成员已停止且根完成、无当前 Plan/Goal/交互的归组场景，成员自己的相位与读态仍由原证据决定。

## 3. 普通 Side 与关系占位

1. 重载恢复精确父子关系后，优先复用当前 owner 快照、已读到的最新轮次和在途 follow。缺终态时复用现有按目标的最新一轮询证和终态门，有限并发与去重。普通 Side 的成功完成需要当前 owner、同轮、空闲、无较新活动及无待办。接受前重新核对父子关系和连接代次。
2. 给私有 Goal 证据带来源。无轮次、运行、待办、Goal 来源或在途核验的精确关系才可标记为仅有关系。实际 Goal、正在核验、读取失败、更新轮次都按现有优先序。Kernel 只在根确凿完成且原生已知未读时，对仅有关系成员采用完成未读归组，未知成员继续限制归档。对外合同及 UI 继续使用现有快照。

## 4. 同步时延与提速

1. 在现有诊断器记录同一匿名目标的首帧、暂存或拒绝、库存准入、重放、owner 请求/回执、原生未读变化、Kernel 归组与任务包版本。Float 发送/应用沿原版本回执。首次阶段有界去重，只记录枚举、时间、状态和版本。能够区分目标帧晚到、库存等待、Host 或 Float 消费等待。发送端时间缺失时，端到 Host 的时间仍保留为未知。
2. 本轮可独立提速的点是现有可信目标核验和批量闭合读取不阻塞库存首包。保持已入库任务的精确启动/终态直接投影。优化库存或调整原生未读上升沿的定向核验优先序，需要同一目标出现可归因的等待记录。待核准目标只暂存，核准后重放，旧 owner、旧域、重复轮次和真实运行均按现有保护。

## 5. 实施与回归

1. 写集为 Codex Host、来源读取、现有诊断、V7 evidence adapter 与 Kernel，必要的只读 SQLite 公用执行器、资产清单和随包校验。Cursor 只接共享的底层只读执行，无状态归组变化。生成的 `public/` 与 `dist/` 由原构建链同步。
2. 本轮 `VerificationImpactTrace` 覆盖 macOS 缺内置驱动、缺库/失败、关闭与明确重开、新活动和换代、普通 Side 的重载询证、关系占位与真实 Goal、未读/清读与归档权限。延迟覆盖先到帧、后到帧、慢库存及重复通知。优先使用现有随包检查和最窄的定向检查，由原 closeout 构建入口执行。
3. 验收保留源码、构建和真实宿主三项证据。实际 uTools 需要验证兼容驱动命中两条海报边、重载后的 Side 成功、BOT 新一轮原生未读清除、启动和完成分别取得一条同目标计时。发现归档或相位保护退化时，可独立撤回闭合、Side/Goal、时延接线，沿用原发布路径。
