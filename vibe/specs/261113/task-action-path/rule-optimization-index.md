## 思路条目

<a id="r01"></a>
### R01 核心方向先行

先给问题、概要路径、影响和控制点；方向认可之后仍按当前阶段推进。用户要求只看方案时，不从先前的整体认可推导功能实施权。全局已有结果、权限与确认前置约束，应检查执行缺口，不重复增加同义禁令。适用O1、O5、O6。

<a id="r02"></a>
### R02 范围变化先失效

用户收窄、停止或撤销动作时，先令旧范围失效，禁止新动作，再停止相关执行者并核清在途结果。停止请求、退出确认、晚到写入和接管归属分别核实；未知结果先对账，不得把unknown当成只读或通过。现有全局权限和唯一写者原则已覆盖主体语义；本项目待补的是Hook入口的可靠消费。适用O1、O2、O5。

<a id="r03"></a>
### R03 文档关联与唯一来源

文档正文保留可审阅的语义，关系和结构化状态通过SQLite查询。每个数据集须声明唯一可编辑来源；本项目试点保持JSON声明、SQLite派生，不在本轮迁移为SQLite主存。既有全局候选已讨论允许明确声明SQLite主存，不能把本地派生模式推广为所有场景的唯一模式。适用O4、O6。

<a id="r04"></a>
### R04 逐目标预防

每个目标挂接适用的风险、触发条件、允许的最小动作、证据与局部停点；执行者开工和交付都能对照。范围外事项只记候选，不变成本批任务。逐目标组织方式是本次试点，尚无新增自动阻断器，也未证明它已减少返工。适用O1–O7。

<a id="r05"></a>
### R05 按承诺核对实际交付

基线、写集、保留行为、实际diff和真实证据逐项比较；遗漏、额外改动、已实现未验和已接受分开。子Agent先报净结果，主控按证据接受；需要独立判断时再复核，不固定每轮启动完整流水线。适用O5、O7。

<a id="r06"></a>
### R06 独立状态维度

证据是否成立、事项如何处置、项目是否采纳、全局是否采纳、是否执行、怎样核验、用户是否接受分别保存。某一维通过不自动推进其它维；缺证据保留unknown。此语义已有全局owner，不因新增字段而另造一套晋升规则。适用O4、O5、O6、O7。

<a id="r07"></a>
### R07 近期对话只抽取净思路

用原生正文核实用户纠正和授权，记录真实可见的来源ID、时间窗口和完整性；标题及summary只用于发现。F1/F2等短选项必须绑定原轮选项，不能因文字相同就在另一任务沿用授权。不要保存原始聊天、提示、命令、推理或输出；没有读到的确认不补写。覆盖缺口只影响依赖该证据的判断。适用O6、O7。

<a id="r08"></a>
### R08 复用有效结果

按实际输入、范围、环境与失效条件复用检查，只补受影响的缺证，不因提交、换代或整理文档重复全量测试。未观察到的成本和节省不填0、不推算。与本次无关的产品功能和其它项目不进入排查写集。适用O2、O4、O5、O6。

### R09 复用执行者和确定性工具

主模型保持核心判断；有界的常规工作复用原执行者和现有工具。独立工作才并行，一份写集一位写者；请求、配置与实际观测模型分开。早期已批准的轻量路由批次不能反向证明后来的候选已批准，也不证明产品构建或生产动作已通过。适用O5、O7。

## 状态与SQLite合同

<a id="state-contract"></a>

现有task-document-catalog/v1不新增字段。每条专用更新的summary为JSON字符串，统一`schema=eypc-task-record/v1`；普通文字更新继续按原工具处理，不强行解析。

现行工具对`updates.summary`按字符串字符数校验，上限为2048字符，包含序列化后的JSON结构。候选状态摘要须在写入和显式重建前按现行工具确认字段限额；容纳不足只保留必要净状态与ID引用，不扩schema、不抬高限额。

| 序号 | 字段 | 本试点含义 |
| --- | --- | --- |
| 1 | kind、entity_id | rule-idea对应R编号；prevention-map对应O编号；source-review对应S编号；consumer对应实际新对话 |
| 2 | evidence_state | candidate / source-verified / verified；只说明该项所引用的证据，不代表功能通过 |
| 3 | disposition | open / accepted / deferred / rejected / resolved；处置结论不等于执行完成 |
| 4 | adoption_project、adoption_global | 项目采纳与全局采纳分开；accepted-plan、pilot、covered-existing、pending-review、not-proposed各保原范围 |

```bash
python3 -B - <<'PY'
import json
import sys
from pathlib import Path

sys.path.insert(0, '/Users/gdkmjd/work/czz/CzzProj/CodeNote/AiRef/VibePractice/Vibe_Rules/scripts')
from task_document_index import Scope, open_index

scope = Scope(Path.cwd(), 'vibe')
with open_index(scope) as (connection, data):
    rows = connection.execute('''
        WITH current_records AS (
          SELECT id, source_ref,
                 CASE WHEN json_valid(summary) THEN summary ELSE '{}' END AS payload
          FROM updates
          WHERE NOT EXISTS (
            SELECT 1 FROM supersessions WHERE supersedes_id = updates.id
          )
        )
        SELECT json_extract(payload, '$.entity_id') AS idea,
               json_extract(payload, '$.adoption_project') AS project,
               json_extract(payload, '$.adoption_global') AS global_adoption,
               json_extract(payload, '$.execution_state') AS execution,
               json_extract(payload, '$.verification_state') AS verification,
               source_ref
        FROM current_records
        WHERE json_extract(payload, '$.schema') = 'eypc-task-record/v1'
          AND json_extract(payload, '$.kind') = 'rule-idea'
        ORDER BY idea
    ''').fetchall()
    result = {'dataset': data['dataset'], 'ideas': [dict(row) for row in rows]}
print(json.dumps(result, ensure_ascii=False))
PY
```
