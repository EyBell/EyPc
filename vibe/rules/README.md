## Project Rules

- Git worktree tasks follow the CodeNote [worktree lane layout](../../../../czz/CzzProj/CodeNote/AiRef/VibePractice/Skills/global/manage-worktree-task/references/worktree-lane-layout.md#L1): branch `<lane>/yyMMdd-<functional-core>`, path `EyPc-worktrees/{lane}/{yyMMdd-<functional-core>}/`, same-round branch+worktree bootstrap, mandatory closeout ask (cleanup / park / continue), index-only batch sync unless the current message explicitly authorizes merge/rebase. Historical paths such as `EyPc-worktrees/260824-...` without a `{lane}/` segment remain adoptable; do not bulk-rename live worktrees.
- EyPc is a uTools plugin, not a standalone Electron app.
- Use Vue 3 + TypeScript + Vite for the UI and runtime.
- Reusable uTools host/preload/window/HMR/packaging/Esc/`mainHide`/hotkey contracts and failure usage are owned by the CodeNote [uTools plugin development module](../../../../../czz/CzzProj/CodeNote/DevelopRef/Multi-System-Use/uTools/README.md#L1). EyPc does not maintain a second full technical archive; project tasks keep only raw/verify evidence and thin local pointers.
- EyPc development uses `dist/plugin.json` as the complete plugin directory and `pnpm run serve` before re-connecting development. Child `createBrowserWindow` pages need their own Vite development proxy; details live in the CodeNote module.
- Any uTools host/preload bridge change must statically search for private synchronous IPC, prove the main entry has no synchronous host dependency, and keep [preload/index.js](../../preload/index.js#L1) and [public/preload.js](../../public/preload.js#L1) behaviorally mirrored. Consensus pointer: [utools-private-sync-ipc-entry-freeze.md](../knowledge/error-memory/utools-private-sync-ipc-entry-freeze.md#L1).
- Keep domain logic pure and testable under `src/domain/`.
- Put uTools, Node.js, shell, process, and file-system calls behind `src/platform/` or `preload/`.
- All user-visible mutations go through Runtime Action dispatch.
- Reusable failures, user corrections, data incidents, and tool/runtime traps must be routed through [error-memory-capture](../../../../../czz/CzzProj/CodeNote/AiRef/VibePractice/Skills/global/error-memory-capture/SKILL.md#L1). uTools-reusable failures archive into the CodeNote uTools module; other project-specific failures remain in project error memory.
- Medium or larger interaction/UI/configuration work must apply the project [developer-soul.md](../knowledge/developer-soul.md#L1) before changing behavior.
- Edit-like interactions must follow the command soul in [developer-soul.md](../knowledge/developer-soul.md#L1): `F2` full edit, `Shift+F2` rename, `Ctrl+S` save, `Escape` cancel, and editor-local `Tab` cycling.
- Shortcut chords are scoped, not globally unique by default. Before treating a shortcut as conflicting, inspect tab, layer, input role, and `when` ownership in [keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L1); the same chord may be reused across mutually exclusive feature tabs or contexts, and UI hints must show the context-local shortcut.
- MQTT connection create shortcuts are focus-scoped in [appRuntime.ts](../../src/runtime/appRuntime.ts#L1): `Ctrl+G` / `Ctrl+N` inherit parent only from explicit row actions or `mqtt-connections` row focus; connection search, blank rail space, and other non-edit MQTT panes create top-level targets while the connection rail is expanded.
- Shortcut hint popovers must render in a top-layer fixed surface, not inside rows, buttons, drawers, or overflow-hidden panels; ordinary shortcut popovers must filter invisible anchors, auto-stagger nearby hints and shift fully inside viewport edges without resizing the source element or being hidden by masks.
- The expanded float's quota area is a single row. Every enabled provider renders inside it; the full window title and reset time live only in the float's own 200ms hint and in each chip's screen-reader text, and the per-provider reading color is a configurable expanded-card token (`codexQuota` / `claudeQuota`), never a hard-coded brand color. This supersedes the earlier bubble-free quota rule for the quota chips only. Consensus: [design-preference-receipt.md](../specs/260805/2051-float-quota-single-line/design-preference-receipt.md#L1).
- Expanded-card interaction hints (status, short actions, confirmation) use the float's own speech-bubble layer. They must not insert an in-flow status row that changes list geometry. Confirmation is immediate and sticky; hover/focus remain 200ms. Consensus: [RAW-175](../specs/260817/1618-float-action-hint-popover/spec.md#L1).
- Product operation tips use the shared [OperationTooltipLayer](../../src/components/OperationTooltipLayer.vue#L1). Icon/action controls must set always-on `data-operation-tooltip` and `data-operation-shortcut` (MQTT helpers: `commandTooltip` / `plainTooltip`); do not rely on native `title` alone or on Ctrl-only `data-mqtt-shortcut-hint`. Consensus: [operation-tooltip-title-only-missing-product-attrs.md](../knowledge/error-memory/operation-tooltip-title-only-missing-product-attrs.md#L1).
- Global Quick Jump markers are the explicit placement exception: every marker stays centered on its target's two-dimensional projection, never title/edge/collision/viewport-shifts away from that center, and uses the fixed pointer-transparent top layer plus the compact framed visual defined by the current product requirement.
- Unspecified visual details, rules, typography and component choices inherit the current project authorities and existing component language. Do not repeatedly ask the user to confirm defaults that those authorities already resolve.
- Authority order for behavioural questions is fixed: platform/safety > the user's current request > [PRODUCT_REQUIREMENTS.md](../specs/PRODUCT_REQUIREMENTS.md#L1) at its current version > task-level spec/raw-requirement > [developer-soul.md](../knowledge/developer-soul.md#L1) > the CodeNote master > tool output. The soul records taste; the product requirement records contract. Before citing any soul clause, search the product requirement for that topic and for `supersede`; a soul clause that has been superseded must be annotated in place with a link to the clause replacing it, never left to be re-cited.
- The [requirement registry](../specs/requirements/README.md#L1) does not compete with that order — it answers a different question. The order says which document wins; the registry says whether a given clause is still current, which part of it survives, and whether a user or an implementer wrote it. Before citing any task-level `RAW-nnn`, check its leaf: a clause can read `active` in its own task document while a later task has already retired part of it, and that partial retirement is visible only in the registry. A clause marked `agent-transcribed` never outranks a `user-stated` one on conflict. When adding or changing a global rule, first search for prior similar requirements — on conflict, surface it to the user and default to the newest requirement rather than silently following either. Consensus: [superseded-rule-cited-as-authority.md](../knowledge/error-memory/superseded-rule-cited-as-authority.md#L1).
- A finding may only be overturned on evidence that was executed, not merely read. Fact claims that decide behaviour ("hiding clears the badge", "this port is wired up") require a run — a probe, a test, or a real invocation — before they may be written into a spec, a receipt, or user-facing help.
- EyPc development verification is impact-based and Agent-executable. Before verification commands enter an Agent-authored or Agent-expanded plan, build a provisional `VerificationImpactTrace`. Frontend/UI/runtime source changes run relevant focused tests and the affected semantic type boundary; add `pnpm run build` only when bundle/output/config/entrypoint behavior is affected. Repository-wide `pnpm run test`, `typecheck`, `build` or `verify` requires a recorded global-testing-owner escalation trigger; approval or implementation of a suite first inserted by an Agent-authored plan is not one. Docs/rules/Skill-only changes run their focused link/rule/package checks instead of unrelated application checks. A passing build may prove compile/package integrity but never substitutes for uTools/native-window/visual/interaction acceptance.
- MQTT tests are outside the default verification set. Do not select `tests/**/mqtt*`, `tests/runtime/action.test.ts`'s MQTT cases or any other MQTT suite for an impact matrix, and do not gate a delivery on them, unless the current request explicitly asks for MQTT verification. **Reporting is unchanged**: if a whole-repository run surfaces an MQTT failure, say so and attribute it, then continue — silence about a known red is not the same as excluding it from the gate. User decision, 2026-08-13.
- Do not run `pnpm run serve`, `dev`, `preview`, watch mode, uTools, a real app/native host, browser automation, screenshots, real Codex preflight, or real archive/project-removal lifecycle operations unless the user directly and explicitly asks for that runtime evidence in the current task. Selecting an implementation option, approving a plan, or asking to fix/verify/finish does not authorize real-plugin testing. Background/headless work may run bounded tests, typecheck and build, but must not launch or keep a runtime process.
- Codex native global state is read-only except for the explicitly confirmed Companion project-removal transaction: the host must reject while Codex Desktop is running, validate a short-lived project alias and source fingerprint against the primary state file, change only the native project registry fields, atomically replace primary plus `.bak`, and verify/rollback. All other Codex flows remain absolutely read-only toward that file.
- Companion providers are separate evidence/side-effect modules behind one interface. `src/domain/companionProvider.ts` is the lowest layer and must not import `codex.ts`. Provider Adapters normalize raw membership/activity/interaction/unread/plan-artifact/metadata/topology evidence and own inspect/open/archive/execute transport effects but never final phase/group/tier/count；`companion-task-kernel-v7` alone reduces member causality、canonical root state、interaction tombstones、Plan artifact、views and capabilities。A current interaction and an executable Plan artifact are never the same fact：artifact-only maps to stopped/待继续；resolve/cancel/execute must atomically advance the Shadow tombstone；request disappearance alone cannot cancel the artifact。Renderer submits only Provider-neutral intent；`companion-task-actions-v3` owns action→Provider dispatch、confirmation and artifact-revision single-flight；`companion-open-handoff-v1` validates dispatch/native-confirmation receipts and never derives opened/read from a Deep Link alone；Controller accepts immutable V7 Snapshots without rebuilding state。Do not retain a second Codex/Claude/Cursor business implementation in Controller、Renderer、Float or Host glue。Each provider is independently enableable；a provider failure degrades that provider alone。
- Every top-level Tab is declared by `FeatureModuleV7` and exposes only a feature-specific `RuntimeSlice`; pages must not receive the full mutable App Runtime snapshot。Buttons、shortcuts、context/More menus、drawers and QuickJump use the same Command Catalog and exact FeatureTarget/NavigationIntent。LayerStack is the only modal/Escape/focus owner，KeybindingIndex filters the active surface before arbitration，and non-surface adapters must not add global keydown owners。Main、Float and Action consume project semantic tokens；raw canvas/surface/text/focus/z-index values belong in token/theme owners，not feature selectors。Consensus: [RAW-179 V7](../specs/260824/eypc-v7-global-refactor/spec.md#L1).
- Companion phase correction is source-structural, never elapsed-time-based. Claude `SessionEnd` may change phase only when the same reducer has observed an open parent Turn；a cold/lifecycle-only tail records lifecycle only and cannot override completed history。A Codex Desktop-only Side relation may be retired only after an accepted complete App Server inventory excludes the child and all three bounded targeted latest-Turn reads return exact empty；any failed/non-empty read、waiting/Plan、confirmed App Server live、newer evidence or incomplete inventory retains it。Do not add TTL/staleness terminal inference. Consensus: [Claude lifecycle error memory](../knowledge/error-memory/claude-generic-session-end-must-not-overwrite-completion.md#L1) · [Codex status error memory](../knowledge/error-memory/codex-provider-status-display-normalization.md#L1).
- Claude native state is read-only with two narrow exceptions. Hook/status-line registration in `~/.claude/settings.json` requires action-time user confirmation, is idempotent and marked, preserves existing hooks/status line, and uninstalls cleanly. RAW-150/154 additionally allow the macOS fixed-grammar versions `1.26832.0`、`1.28929.0` and `1.30096.5` D′ archive Adapter to update only `isArchived=true` in one uniquely indexed App-local `local_*.json`: it must revalidate identity/phase/stat/hash, use same-directory atomic replace, prove metadata+inventory convergence, restore original bytes only when no concurrent write occurred, and never Deep Link, use AX/JXA, scan-modify sessions, write LevelDB/non-target files, or expose a path outside Preload. Conversation content, tool arguments and credential values must never enter an observation, a diagnostic or a persisted file.
- Do not delete real files from disk in the favorites feature; removing a favorite only removes plugin metadata.
- Process termination is high risk: normal kill requires confirmation; force kill is allowed only for explicit selected PID + verified port match.
- Every tool actually used on this repository needs a repository-owned entry file that the tool reads natively: Claude Code reads [CLAUDE.md](../../CLAUDE.md#L1), Codex reads [AGENTS.md](../../AGENTS.md#L1). `AGENTS.md` is the canonical adapter body and `CLAUDE.md` is its mirror — change both together. Global-hook injection is redundancy, never the sole path: rules present in context do not prove the repository can load them, so classify how each layer arrived before calling a chain healthy. Adapters route and state only non-inferable facts; they never restate the CodeNote master or facts this file already owns. Consensus: [hook-injection-mistaken-for-repo-discovery.md](../knowledge/error-memory/hook-injection-mistaken-for-repo-discovery.md#L1).
- Every top-level feature in [featureRegistry.ts](../../src/runtime/feature/featureRegistry.ts#L1) must ship a matching end-user operation guide registered by [guides/index.ts](../../src/help/guides/index.ts#L1); new `AppTabId` / feature types and user-visible feature behavior changes must add or update that guide in the same change. Rule detail: [documentation.md](documentation.md#feature-help-guides-required).
