# EyPc Architecture

Tool: codex

## Product Scope

EyPc is a keyboard-first uTools plugin for local PC capability calls. The first version provides port process management and file/folder favorites.

## Layers

```text
uTools feature entry / keyboard input
  -> Interaction Runtime
  -> Keybinding Runtime
  -> Action Runtime
  -> Domain services
  -> Platform bridge / preload
  -> UI projections
  -> uTools storage
```

## Invariants

- Action Runtime is the only user-visible mutation entry.
- Domain functions are pure and covered by tests.
- Platform functions isolate shell, process, file, and uTools APIs.
- UI renders projections and dispatches intents; it does not call shell commands directly.
- Project interaction taste is recorded in [developer-soul.md](developer-soul.md#L1); it guides medium or larger UI, shortcut, drawer, and AI-rule work before implementation details.
- Favorites removal never deletes disk files.
- Force-kill actions must be scoped to selected PID and verified port match.
- Port group cleanup expands configured group entries through the domain layer, then filters against the current scan before any kill request.
- Port scan results are deduped by `pid:port:protocol` in [src/domain/ports.ts](../../src/domain/ports.ts#L1), and duplicate listener addresses are merged before UI projection.
- Port search ranks exact, prefix, contains, and regex matches in [src/domain/ports.ts](../../src/domain/ports.ts#L1); regex group rules match full process text in [src/domain/ports.ts](../../src/domain/ports.ts#L1).
- Port groups are user-defined only; state normalization removes legacy `default:*` groups in [src/domain/state.ts](../../src/domain/state.ts#L60).
- Port groups support folders through `PortGroupFolder` and `PortGroupTarget` in [src/domain/types.ts](../../src/domain/types.ts#L23); normalized state keeps `folderId`, `sortOrder`, and collapsed folder ids in [src/domain/state.ts](../../src/domain/state.ts#L160).
- Port group tree projection, folder search, folder rule union matching, and group-to-folder moves are pure domain helpers in [src/domain/ports.ts](../../src/domain/ports.ts#L251).
- Ports UI uses a two-pane group/results model with collapsible group folders, inline group/result search, drag-to-folder movement, and group editing in [src/pages/PortsPage.vue](../../src/pages/PortsPage.vue#L110).
- Port-tab keyboard focus reserves `tab` and `s-tab` for group/results pane cycling in [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L1). Global tab switching uses dynamic `c-s-num` labels only for non-settings visible feature tabs so inner `c-num` commands remain available; settings opens through fixed `c-a-s` (`Ctrl+Alt+S`) in [src/runtime/feature/featureRegistry.ts](../../src/runtime/feature/featureRegistry.ts#L1) and [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L1).
- Top-level feature visibility is persisted in `settings.featureConfigs` from [src/domain/types.ts](../../src/domain/types.ts#L1) and normalized in [src/domain/state.ts](../../src/domain/state.ts#L1): `favorites` is hidden by default, `settings` is always enabled, and visible Tab order drives [src/components/TabShell.vue](../../src/components/TabShell.vue#L1), runtime tab switching, and `Ctrl+Shift+数字` bindings through [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1). Disabled uTools feature entries route back to Settings feature maintenance through [src/runtime/feature/featureRouting.ts](../../src/runtime/feature/featureRouting.ts#L1).
- Shortcut resolution is layered, not flat: command profiles in [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L1) resolve by layer priority, source weight, command weight, `when` specificity, and declaration order.
- Default shortcut values are maintained as a command-keyed JSON-style map in [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L163), then projected into runtime bindings through [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L247) so settings rows and key resolution share one default source.
- Shortcut overrides are command-level state keyed by `commandId`; [src/domain/state.ts](../../src/domain/state.ts#L1) migrates legacy `shortcutId` into `shortcutIds`, while [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1) persists multi-binding and enabled/disabled overrides.
- Shortcut persistence is profile-based: [src/domain/types.ts](../../src/domain/types.ts#L1) stores `global`, `ports`, `favorites`, and `settings` profiles while preserving the legacy aggregate for compatibility.
- Shortcut codec, physical-key fallback event extraction, and Ez short-chain display are centralized in [src/domain/shortcuts.ts](../../src/domain/shortcuts.ts#L1), then reused by keyboard runtime, Settings, command hints, and tab labels.
- Legacy search-history state is still normalized for local-storage compatibility in [src/domain/state.ts](../../src/domain/state.ts#L1) and [src/domain/searchHistory.ts](../../src/domain/searchHistory.ts#L1), but the UI/runtime no longer exposes search-history suggestions, dropdowns, writes, or shortcut commands.
- Settings shortcut governance lives in [src/pages/SettingsPage.vue](../../src/pages/SettingsPage.vue#L1): the page uses uTools/EzClipboard-style `快捷键` / `维护` sub tabs, keeps shortcuts in a compact command-id-first worktable, moves Chinese command titles into fast mouse-following upper tooltips with complete multiline content, hides default bindings from the main row into hover/edit surfaces, uses English profile/layer scope chips, and shows layer recovery commands, shortcut resolution preview, storage status, and reservation rules in a left-nav maintenance tab with one stable center domain. Shortcut recording follows local EzClipboard current/pending/capture/direct-input/default-restore management, but edits land in a Settings-local draft until [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1) commits all shortcut profiles through `saveShortcutProfiles`. Settings-local `Ctrl/Cmd+F` focuses the shortcut search input without changing the global `search.focus` command, and the settings shortcut search field shows a compact `c-f` hint only while Ctrl/Command is held.
- `esc` is modeled as layer commands in [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1): nested interactions return one layer at a time, and idle port state returns unhandled so the uTools host can exit the plugin.
- Edit layers use command-soul semantics in [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L1): `f2` opens full edit, `s-f2` opens rename, `c-s` and `c-cr` save, `esc` cancels, and `tab` / `s-tab` cycle fields inside the active editor only.
- Ordinary port groups can change folder ownership through the command-backed `c-f2` action in [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L185) and [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1041): it opens a folder-only group editor in [src/pages/PortsPage.vue](../../src/pages/PortsPage.vue#L501), where `del/backspace` on the folder select clears `folderId` so the group returns to the root level.
- Port search focus is command-specific: `c-f` focuses port-result search and `c-s-f` focuses group search through [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1) and [src/App.vue](../../src/App.vue#L1). Command-driven search focus clears stale port and group row highlights first, so the input becomes the only logical focus until list movement or filtering establishes a fresh row.
- Port-page row focus is mutually exclusive across panes: result-row focus clears group-row focus, and group-row focus clears result-row focus in [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1). [src/pages/PortsPage.vue](../../src/pages/PortsPage.vue#L1) only paints group `focused` / `selected` row highlight while the group pane owns logical focus, so filter context never appears as a second movable focus beside result focus.
- Port search inputs are action-aware plain filters: result search keeps `↑↓` on result-row focus while focused `cr` is inert; group search keeps `↑↓` on group/folder focus and lets `cr`, `s-cr`, `F2`, `s-F2`, `del/backspace`, `c-del/c-backspace`, `c-cr`, `c-←`, and `c-→` run the same commands as the non-search group pane through [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L1) and [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1).
- Port group search and pane activation normalize to the first visible group or folder so group commands remain active before arrow movement from the group search input in [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L1) and [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1).
- Shift preview in the port group pane renders a readonly group editor projection and does not open the mutable editor draft; it is constrained to the active group-pane logical focus, an open group side panel, a focused group target, and no active editor/confirm/drawer/detail layer in [src/pages/PortsPage.vue](../../src/pages/PortsPage.vue#L1).
- Port group folder rename and context menus are command-backed: `F2` on a focused folder opens the rename-only group editor through [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1265), the drawer exposes rename for folder targets in [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L449), the editor title reflects folder rename through [src/pages/PortsPage.vue](../../src/pages/PortsPage.vue#L67), and right-click on any group/folder row focuses that target then opens the action drawer in [src/pages/PortsPage.vue](../../src/pages/PortsPage.vue#L104).
- The port group side panel is toggled through the command-backed default `c-s-w`; the binding is configurable through shortcut settings in [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L1) and [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1), while individual group folders use `←/→` collapse and expand commands.
- Top-level tabs and port search inputs stay compact by default: [src/App.vue](../../src/App.vue#L1) tracks held Ctrl/Command state, [src/components/TabShell.vue](../../src/components/TabShell.vue#L1) reveals `c-s-1`, `c-s-2`, or settings `c-a-s` as right-edge floating hints without widening fixed-width feature tabs, and [src/pages/PortsPage.vue](../../src/pages/PortsPage.vue#L1) passes Ctrl-based search command hints into [src/components/SearchSuggestBox.vue](../../src/components/SearchSuggestBox.vue#L1) only while that modifier is held. Search inputs keep placeholders left-aligned, reserve only a compact right-side hint area in [src/styles/app.css](../../src/styles/app.css#L1), and hide the hint when the current command label no longer contains a `c-` binding.
- Shortcut help is no longer a bottom footer: [src/components/TabShell.vue](../../src/components/TabShell.vue#L1) renders a top-right `?` trigger and shows [src/components/CommandHints.vue](../../src/components/CommandHints.vue#L1) in a hover/focus popover. The hint content summarizes `c-*` bindings as a system-aware hold-modifier prompt (`Ctrl` outside macOS, `⌘` on Apple platforms), while keeping immediate non-Ctrl actions such as arrows, `cr`, `del/backspace`, `c-del`, `esc`, and `s-esc` visible.
- `s-esc` is the global app-hide command above all interaction layers. Runtime dispatch calls [src/platform/eypcPlatform.ts](../../src/platform/eypcPlatform.ts#L1); preload maps it to uTools `hideMainWindow(true)` in [preload/index.js](../../preload/index.js#L1), while browser fallback reports unsupported without throwing.
- Result-pane process kill defaults are `del` / `backspace` for confirmed kill and `c-del` / `c-backspace` for force kill; these bindings are blocked while text inputs are focused and do not replace group kill shortcuts in [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L1).
- Group-pane metadata deletion defaults are `del` / `backspace` for confirmed delete and `c-del` / `c-backspace` for forced delete in [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L1). [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1) deletes only plugin group/folder metadata; deleting a folder cascades child groups, removes the collapsed folder id, clears matching group filter/detail/drawer state, and moves focus to the next visible group/folder.
- Port drawers are explicit runtime projections in [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1): result pane `c-←` opens the left single-process detail drawer, group pane `c-←` opens group/folder detail, `c-→` opens the right action menu, and multi-select does not auto-open a drawer.
- Port group apply is split: `cr` filters only when focus is outside text inputs, while `c-cr` filters, switches to results, focuses the first matched port, and multi-selects all matched ports in [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1).
- Port page `esc` recovers inward before exiting outward: confirmation/editor, active detail/drawer, multi-select, focused search clear/blur, group filter, and focus are handled in [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1); when search text exists, one focused `esc` clears the query and requests blur instead of spending a separate blur step. When no layer remains, the shortcut is unhandled so the uTools host can exit.
- Port search opening and first typed query auto-trigger scan through [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L183), and uTools port entry dispatches search focus in [src/App.vue](../../src/App.vue#L64).
- Search blur after `esc` is requested by runtime and applied in [src/App.vue](../../src/App.vue#L1), avoiding implicit focus-to-row jumps.
- Cross-platform scan commands are centralized as macOS/Linux `lsof -nP -iTCP -sTCP:LISTEN` and Windows `netstat -ano -p tcp` in [src/platform/processBridge.ts](../../src/platform/processBridge.ts#L8), with absolute-path GUI host candidates in [src/platform/processBridge.ts](../../src/platform/processBridge.ts#L13) and [preload/index.js](../../preload/index.js#L25).
- Local browser dev mode mirrors uTools process termination through POST `/__eypc__/ports/kill` in [src/platform/devPortServer.ts](../../src/platform/devPortServer.ts#L1); it re-scans before kill and refuses requests when PID no longer owns the requested port.
- Browser fallback storage persists normalized state to `localStorage['eypc/state/v1']` in [src/platform/eypcPlatform.ts](../../src/platform/eypcPlatform.ts#L1); uTools runtime storage continues to use preload `dbStorage`.
- Favorite path picking is an optional platform capability; unavailable hosts must return `null` and preserve manual path entry.
