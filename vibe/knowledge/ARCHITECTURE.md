# EyPc Architecture

Tool: codex

## Product Scope

EyPc is a keyboard-first uTools plugin for local PC capability calls. Current feature areas are port process management, file/folder favorites, window jump/favorites, MQTT over WebSocket, and a Codex/Claude multi-provider quota/task companion.

## Layer Model

```text
uTools feature entry / keyboard input
  -> Interaction Runtime
  -> Keybinding Runtime
  -> Action Runtime
  -> Domain services
  -> Platform bridge / preload
  -> UI projections
  -> uTools storage / local archive
```

## Core Invariants

- Action Runtime is the only user-visible mutation entry.
- Domain functions are pure and covered by tests where behavior is non-trivial.
- Platform functions isolate uTools, shell, process, file-system, clipboard, and local storage APIs.
- Reusable uTools host contracts (packaging, child-window HMR, redirect-only hotkeys, Esc capture, `mainHide` diagnostics) are owned by the CodeNote [uTools module](../../../../../czz/CzzProj/CodeNote/DevelopRef/Multi-System-Use/uTools/README.md#L1); this file keeps EyPc feature implementation only.
- UI renders projections and dispatches intents; it does not call shell, storage, MQTT, or filesystem side effects directly.
- Project interaction taste is recorded in [developer-soul.md](developer-soul.md#L1).
- Process status and task routing live in [../specs/PROJECT_STATUS.md](../specs/PROJECT_STATUS.md#L1), not in architecture memory.
- Current product contracts live in [../specs/PRODUCT_REQUIREMENTS.md](../specs/PRODUCT_REQUIREMENTS.md#L1).
- Current MQTT implementation mapping lives in [../specs/2606231645-eypc-mqtt-websocket-tab/06-sync-doc.md](../specs/2606231645-eypc-mqtt-websocket-tab/06-sync-doc.md#L1).
- Verification is impact-driven. Root [package.json](../../package.json#L1) exposes a non-running `verify` lane that synchronizes canonical uTools preload mirrors, runs the complete test suite, then performs semantic typecheck, production build, runtime preparation and package validation. [scripts/utools-preload-assets.mjs](../../scripts/utools-preload-assets.mjs#L1) is the shared manifest consumed by sync, prepare and validation so main/float/action preload paths are not re-declared across scripts.

## Ports

- Port scan results are normalized and deduped in [src/domain/ports.ts](../../src/domain/ports.ts#L1).
- Port groups/folders are plugin metadata stored in normalized state, not filesystem or OS process objects.
- Process kill actions must stay behind runtime/platform bridges and revalidate selected PID/port ownership before side effects.
- Force kill is allowed only for explicit selected PID plus verified port match.

## File Favorites

- Favorites are plugin metadata for real file/folder paths and virtual groups.
- Removing a favorite never deletes real files from disk.
- Persistent favorites pass through deterministic graph normalization before tree or ancestor traversal. Duplicate IDs are rebuilt, invalid parent chains return to root, and traversal keeps independent visited defenses in [src/domain/favorites.ts](../../src/domain/favorites.ts#L1).
- Display paths remain user/host values. A separate identity key makes Windows drive and UNC separator/case variants equivalent while preserving POSIX case and legal backslashes.
- Favorites open/reveal/copy stays behind [src/platform/eypcPlatform.ts](../../src/platform/eypcPlatform.ts#L1) and [preload/index.js](../../preload/index.js#L1). Outcomes distinguish confirmed success, host dispatch, reveal-as-open fallback, and failure; capability and inspection data are Runtime-only.
- [src/domain/favoriteLaunch.ts](../../src/domain/favoriteLaunch.ts#L1) owns ten platform-isolated slot defaults, runner normalization/trust fingerprints, placeholder resolution, absolute/PATH executable rules, target-directory resolution and bounded 30-day-half-life search affinity. State migration in [src/domain/state.ts](../../src/domain/state.ts#L1) supplies empty slots/learning to old data while preserving malformed runner metadata only for repair; malformed or fingerprint-mismatched runners cannot execute.
- Runner execution is a structured platform port: Runtime resolves and rechecks trust, then [preload/index.js](../../preload/index.js#L1) validates target/cwd/executable and starts only argument arrays with `shell:false`. Background children detach with ignored output; terminal mode uses static macOS AppleScript, Windows PowerShell payload or known Linux terminal adapters and never falls back to background. PowerShell launch does not alter machine execution policy.
- Runtime owns `containers | items | directory`, explicit/drawer/focus/visible-selection target priority, request generations, batch constraints and removal confirmation in [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1). One-step metadata undo restores original node order and removed collapse state; it restores pane/focus/selection only while the user has not navigated away from the post-removal context.
- Runtime also owns one launch path shared by double-click/Enter/quick-number/slot, successful-use recording, slot repair routing and deletion cleanup. Only accepted default open or runner start updates global/query learning; locate/copy/failure do not.
- Quick favorite entry atomically clears management transients, requests search-input focus and highlights its first cross-group result. [src/domain/favorites.ts](../../src/domain/favorites.ts#L1) sorts by text tier, query affinity, global frecency and manual order; [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L1) gives an open drawer priority over the page-level `Ctrl+1…0` result actions. Management writes stay in the full favorites page.
- Stable routes `eypc-favorite-slot-1`…`10` are `mainHide` features in [public/plugin.json](../../public/plugin.json#L1). Bindings persist by platform; an unsuccessful slot shows the full favorites slot manager, while a successful launch does not show the uTools main window. Fixed-corner launch is explicitly outside this architecture increment and would use a separate controlled window.
- One-level directory reads do not recurse or navigate. Resolvable file/folder symbolic links retain target metadata, while sockets/devices/FIFOs and unresolved links are omitted instead of being misclassified as actionable files. No bridge method creates, moves, renames, or deletes a real file.
- Pane cycling produces an explicit DOM-focus request and keeps only the active pane's row focus. The narrow container layer becomes visible immediately on open and hides after its close animation so focus handoff never targets a hidden tree. Dialog restoration uses ordered visible fallbacks and a bounded render-frame retry when the original trigger disappears.

## Window Jump Workbench

- [src/domain/windows.ts](../../src/domain/windows.ts#L1) separates raw `NativeWindowObservation` from admitted `LiveWindow`, owns title-blind `WindowFamily { root, children }` generation, relation/capability evidence, explicit `root-current`/`member-exact` requests, persisted discriminated `WindowTarget`, target resolution and ten-slot lookup. App/PID/title/position/size/list order never prove a relationship. [src/domain/windowTree.ts](../../src/domain/windowTree.ts#L1) is the only Window product/workbench-tree framework: ordinary real root/child rows, Finder/Explorer virtual-parent/real-root exception, retained target/slot projection, tree sorting, search flattening, action contexts, root-only selection, navigation and focus recovery. It reuses [src/domain/listSelection.ts](../../src/domain/listSelection.ts#L1) internally.
- [src/domain/windowRebind.ts](../../src/domain/windowRebind.ts#L1) is the framework boundary for session-only manual replacement. One discriminated state owns target, candidates, originating slot and focus return; inventory absence can request an exact probe but can never clear persistence. Slot confirmation activates first and then reuses/creates an exact target while remapping only that slot.
- [src/domain/state.ts](../../src/domain/state.ts#L1) normalizes user-created target metadata (`lastKnownTitle`, bridge-verified `lastInstanceId`, `lastNativeRef`, local pin) plus platform-separated slot IDs. Legacy `titleLocator` migrates only into display metadata and title history is discarded. Live rows, foreground and minimized state remain Runtime session memory only (`windowListLoaded` / `windowCacheUpdatedAt`).
- [src/platform/eypcPlatform.ts](../../src/platform/eypcPlatform.ts#L1) presents capability/list/`probeInstance`/activation/topmost/close/terminate with stale-preload and browser fallbacks. Activation is `root-current` or `member-exact`; liveness is `live | gone | indeterminate`, and only matching `verified-gone` evidence may clear a locator.
- [preload/windows/index.cjs](../../preload/windows/index.cjs#L1) composes the lazy WJ-22 window facade and shared bounded result/trace protocol. [session-cache.cjs](../../preload/windows/session-cache.cjs#L1) owns per-instance liveness and Space bindings plus per-display current Space; [native-command.cjs](../../preload/windows/native-command.cjs#L1) owns bounded privacy-safe native execution; [macos-space.cjs](../../preload/windows/macos-space.cjs#L1) owns direct/reverse SkyLight resolution and target-display-only switching. [macos.cjs](../../preload/windows/macos.cjs#L1) exclusively owns AX/CG list, exact probe/activation/close and permission routing; [win32.cjs](../../preload/windows/win32.cjs#L1) exclusively owns EnumWindows, PID+HWND probe, foreground protection, topmost, close and terminate. Canonical modules mirror byte-for-byte to public/dist and module failure degrades only windows.
- [preload/index.js](../../preload/index.js#L1) now contains no AX/CG/SkyLight/User32 script or window-operation implementation; it only performs guarded CommonJS loading, dependency injection, isolated unavailable fallback and `window.eypcPlatform.windows` mounting. macOS inventory is always a partial current projection; `kCGWindowIsOnscreen` is not liveness. A warm Space binding refreshes only managed-display state, a cold miss resolves only the target, and stale cache eviction retries that target once before failure. Exact AX/HWND final focus remains mandatory. Bridge revision is `wj22-native-instance-space-cache`.
- [src/runtime/window/windowInventoryRuntime.ts](../../src/runtime/window/windowInventoryRuntime.ts#L1) owns complete/partial family merging and freshness, while [windowActivationRuntime.ts](../../src/runtime/window/windowActivationRuntime.ts#L1) owns native request construction and Space failure classification. [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1) orchestrates the exact liveness clear gate, diagnostics, persistence and UI effects. No inventory—complete or partial—proves death by itself.
- [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1) does not auto-scan on Tab entry. It calls one `buildWindowTreeRows` projection and retains native/persistence/message/focus side effects. Root rows and slots dispatch `root-current`; child rows dispatch `member-exact`; file-manager virtual parent landing remains `focused → persisted last → session recent → visible order`. Only root/group native success may commit target metadata.
- [src/pages/WindowsPage.vue](../../src/pages/WindowsPage.vue#L1), [src/runtime/keybinding/keybindingRuntime.ts](../../src/runtime/keybinding/keybindingRuntime.ts#L1), and [src/runtime/keyboardEvent.ts](../../src/runtime/keyboardEvent.ts#L1) render one Vue-native ARIA tree. Ordinary roots/children are level one/two; Finder/Explorer remains virtual parent/real root at level one/two with no third level. Search temporarily expands matching children without overwriting manual state; hiding, collapsing or losing a child restores root focus. Right-click uses `window / child-window / file-manager-group / selection / slot`; child context is exact activate, optional exact close, readonly details and Windows HWND copy. Children cannot persist, select, favorite, pin, edit, bind slots, topmost, force or join batch actions.
- Static manifest entries `eypc-window-slot-1` … `eypc-window-slot-10` use `mainHide: true` and route through [src/runtime/feature/featureRouting.ts](../../src/runtime/feature/featureRouting.ts#L1) while restoring the previous Tab. Window routes do not schedule a generic hide; only Runtime hides after activation success and explicitly calls the workbench/settings fallback on a global-slot failure. Their labels do not depend on aliases; EyPc can open the official uTools setting for a slot but never reads or copies its host binding.

- Feature visibility/order is normalized in app state and rendered by [src/components/TabShell.vue](../../src/components/TabShell.vue#L1).
- Runtime tab switching uses dynamic visible-feature order; Settings has a fixed shortcut entry.

## Shared Help And Command Panels

- [OperationTooltipLayer.vue](../../src/components/OperationTooltipLayer.vue#L1) is the single delegated main-app product-help owner. It resolves the nearest button, actionable row/tree, draggable or form operation control; normalizes explicit metadata, native title fallbacks and legacy `data-tip` detail; separates only shortcut-shaped title suffixes; refreshes an active tip when control metadata changes; suppresses duplicate native titles; attaches `aria-describedby`; captures pointer movement for disabled controls; and clears/suspends on operation, blur or Quick Jump. [app.css](../../src/styles/app.css#L1) disables the Codex main-page pseudo-tip inside `.app-shell`, while the separately rendered Float child remains outside this owner and keeps child-owned hints.
- Runtime panel actions resolve targets as `explicit args → open frozen target → current pane focus → visible selection`. An explicit but invalid ID fails; it never falls through to an unrelated frozen or focused target. Ports, Favorites and MQTT store panel target state in Runtime; Settings keeps command-row detail/action state locally because shortcut drafts are component-owned.
- `Ctrl/Cmd+ArrowLeft/Right`, row-local buttons and context-menu entries converge on the same detail/action action ids. Text editing roles retain native arrow ownership.
- Panel presentation is inside the active Tab: docked at wide widths, reduced-secondary-navigation from `721–1100px`, and exclusive content at `<=720px`. Only confirmation, destructive decisions and atomic editors remain modal.
- Each panel transition captures the trigger, focuses the newly rendered side even when the panel was already open, traps its local Tab cycle where applicable, and restores a stable owner on close.
- [quickJumpLayout.ts](../../src/domain/quickJumpLayout.ts#L1) is a pure target-center projection: each rendered badge keeps its target rectangle's exact center regardless of label width, nearby markers or viewport edges. The overlay owns only Z-axis presentation and never changes source layout or pointer ownership.

## MQTT State And Storage

- MQTT is a default-visible top-level feature declared in feature routing and lazy-loaded from [src/App.vue](../../src/App.vue#L1).
- MQTT domain contracts live in [src/domain/types.ts](../../src/domain/types.ts#L1), normalization helpers live in [src/domain/mqtt.ts](../../src/domain/mqtt.ts#L1), connection tree projection/move helpers live in [src/domain/mqttConnectionTree.ts](../../src/domain/mqttConnectionTree.ts#L1), and lossless versioned multi-record JSON projection lives in [src/domain/mqttExport.ts](../../src/domain/mqttExport.ts#L1).
- Connection configs persist endpoint, client id, username, subscriptions, aliases, colors, publish defaults, reconnect flags, `groupId`, `syncRecords`, layout prefs, and view prefs.
- MQTT connection groups are plugin metadata stored in `MqttState.connectionGroups`; they define connection hierarchy only and must not imply MQTT broker-side resources.
- Collapsed MQTT connection groups persist in `MqttLayoutPrefs.collapsedConnectionGroupIds`.
- Password/token values are excluded from persisted domain models, archives, SQLite mirrors, and publish templates; [preload/index.js](../../preload/index.js#L1) persists them only as an encrypted local userData envelope in `mqtt-secrets-local.json`, using Electron safeStorage when available and AES-256-GCM with the local-only key file `mqtt-secrets-local.key` as fallback.
- MQTT archive durability is SQLite-first through [preload/index.js](../../preload/index.js#L1), with legacy archive fallback surfaced by [src/platform/eypcPlatform.ts](../../src/platform/eypcPlatform.ts#L1).
- `syncRecords=false` is a user-facing sync/privacy preference, not a local durability kill switch.

## MQTT Runtime

- MQTT runtime state and action registration live in [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1).
- Runtime owns connection lifecycle, archive loading, record projections, focus targets, drawers, preview state, draft-history state, layout prefs, and view prefs.
- Runtime owns MQTT connection tree projection, group focus/edit/rename/move-parent/delete/collapse/expand, and drag/drop moves. Group focus must not switch the active MQTT connection config.
- MQTT shortcut context carries `mqttTargetKind` so connection-pane edit shortcuts can route config rows and group rows through distinct action ids without duplicate ambiguous bindings.
- `MqttState.viewPrefs` persists the last `全/收/发/藏` filter and valid per-connection topic filters.
- `MqttArchiveState.publishDraftHistory` stores overwritten/manual publish drafts only and never duplicates real outgoing send records.
- `MqttPublishTemplate.operatedAt` is the publish-template operation-order field with legacy fallback to `updatedAt` / `createdAt`.
- Runtime-owned transient layers, such as draft-history popover/editor, must be represented in shortcut context before DOM focus is trusted.
- Runtime owns MQTT merged-export target resolution and accepts only explicit selected IDs from the requested current list. It preserves visible row order and selection, then routes copy/save through named actions; the save action crosses the platform boundary only after the user chooses a host path.

## Companion Providers

- The floating companion aggregates more than one agent host. [src/domain/companionProvider.ts](../../src/domain/companionProvider.ts#L1) is the lowest layer and imports nothing: it owns `CompanionProviderId`, task-key namespacing, provider enablement, the shared latest-question comparator, Provider-neutral target/action/result unions and `CompanionProviderAdapter`. `codex.ts` depends on it, never the reverse, so display and cycle order cannot drift apart.
- Task keys are namespaced per provider. Codex keys stay byte-identical to the existing inventory so persisted aliases, pins, hides and receipts migrate at zero cost; every other provider is explicitly prefixed (`claude:<sessionId>`) and therefore cannot collide. `CodexTaskCard.provider` is optional and absent on every legacy card, so readers must go through `companionTaskProvider()` rather than reading the field.
- [codex.ts](../../src/domain/codex.ts#L1)、[companionProvider.ts](../../src/domain/companionProvider.ts#L1) and [companionAggregate.ts](../../src/domain/companionAggregate.ts#L1) share one latest-question comparator. Dynamic display first groups by status, then every group orders `latestQuestionAt DESC → createdAt DESC → anonymous key`; generic cycle selects the first non-empty attention/Plan/active/local-pin tier and uses the same order inside that tier. Provider and pin never override recency. Dedicated attention actions retain their own unseen-instance progress rather than consuming the generic cursor.
- [codexController.ts](../../src/runtime/codexController.ts#L1) owns the two attention queues. Persisted `attentionOpenHistory` stores at most 200 anonymous `task key + statusEnteredAt + openedAt` instances per kind, is pruned when a task leaves the group or enters a new state epoch, and advances only after Host-confirmed open—including manual row opening. A new instance preempts, then older unseen entries resume; after all current instances are seen, the next successful action wraps from newest. The Renderer never selects `[0]` or stores request content.
- [src/domain/companionAggregate.ts](../../src/domain/companionAggregate.ts#L1) folds a foreign provider's cards into the Codex `ConversationSnapshotV1` additively and in order, then builds a read-only virtual project projection. Exact stable project key wins; normalized name merges only when unique on both sides; ambiguous names stay separate and Claude-only projects are materialized. The Controller strips foreign cards before every replace merge, and project/task counters are recomputed from the final arrays.
- Provider enablement lives in `CodexSettings.providers` and normalizes any absent or malformed value back to Codex-only. Codex-only keeps its data/state semantics; every rendered task now intentionally carries an explicit textual Codex/Claude ownership marker because RAW-022 supersedes the older “marker only when mixed” presentation rule.
- [companionPresentation.ts](../../src/domain/companionPresentation.ts#L1) is the sole task/project ownership-label projection; [FloatApp.vue](../../src/FloatApp.vue#L1) resolves each marker once while constructing its render row and reuses it for visible text, tint and accessibility. [codexEnvironmentPresentation.ts](../../src/domain/codexEnvironmentPresentation.ts#L1) likewise owns the Codex Runtime banner, diagnostic grid, compatibility-pending predicate and launch help; [CodexPage.vue](../../src/pages/CodexPage.vue#L1) only renders the resulting projection. A manual launch-path set/clear already returns the freshly inspected environment, so [codexController.ts](../../src/runtime/codexController.ts#L1) publishes that result directly and must not trigger a second full inspection.
- [src/domain/companionPresentation.ts](../../src/domain/companionPresentation.ts#L1) owns presentation policy: which provider feeds each water-ball channel, when a row marker is meaningful, and the Claude quota section. Renderers consume its result and make no provider decisions of their own.
- [preload/companion/task-actions.cjs](../../preload/companion/task-actions.cjs#L1) is the single `companion-task-actions-v2` Dispatcher. Anonymous key is open identity；Renderer-supplied alias/revision/phase is only a hint。If the Host registry already has that key，`resolveOpenTarget` uses the current Host target and never rejects an older UI target；only a missing Host target/private mapping enters provider-scoped exact resolution and a same-key single retry。`open` keeps leading-immediate/final-trailing navigation；`archive` remains uncoalesced；`pause/resume/executePlan` join only the same Provider+task+Plan-revision single-flight。Execute confirmation lasts five seconds and is canceled by phase、Plan revision、alias、activity or pending-selector changes；the first click sends no Provider RPC。An exact completed actionable Plan remains pausable/resumable/executable even when no dedicated `Implement Plan` request exists；`planImplementation` changes cycle priority only。On confirmation the Host rechecks latest Turn、real activity and other pending，then the Codex adapter renews only the same key and performs exact open → `thread/resume(excludeTurns=true)` → exactly one `turn/start`；it prefers full default CollaborationMode with current model/effort and otherwise sends the private fixed implementation instruction to that same task without the optional mode object。Indeterminate timeout uses targeted reread without blind resend.
- [task-kernel.cjs](../../preload/companion/task-kernel.cjs#L1) exposes `companion-task-kernel-v4` and [companionTaskPackage.ts](../../src/domain/companionTaskPackage.ts#L1) defines `companion-task-package-v4`. Provider adapters emit normalized evidence only；the Kernel is the single branch/parent reducer、Plan lifecycle store、canonical view/capability selector and process latest cache；the TypeScript projector atomically materializes those selectors without a second phase decision。The Kernel owns membership、phase、tri-state unread、freshness、`planReady/planLifecycleRevision/paused`、dynamic-window membership、groups/counts、badges、attention/cycle keys and capabilities。Every confirmed root/Side bead participates in one reduction；after retained input/approval/Plan/Goal causality，running outranks completed-unread and completed，and latent unread cannot create a second unread group/count while the parent is active。Observation/source generations and Renderer focus remain non-semantic process context；a focus-only configure updates the retained Host Actions target without advancing package revision、publishedAt or listeners and therefore cannot re-filter/reclassify Main or Float。`getLatest/subscribe(afterRevision)` plus Main/Float/Navigation/Actions fingerprints make equivalent polling a complete end-to-end no-op。New root membership still creates a minimal card，inventory remains uncapped，and a missing/incompatible V4 facade is `reload-required` without an older reducer fallback.
- [preload/index.js](../../preload/index.js#L1) is the Codex Evidence Adapter, not a second consumer-side reducer. Exact waiting、active、completed and interrupted evidence enters Kernel immediately；a cold/reconnect interrupted/failed conflict triggers one task-scoped single-flight latest-Turn read。An unconfirmed terminal preserves the previous stable phase with `freshness=verifying` instead of forcing running or inventing a terminal。`unknown` is an abstention：existing inventory semantics remain unchanged and a new hydration-only active row starts from unknown rather than a fabricated running baseline；the 250ms window verifies but never grants permission to invent a phase。A process-private Desktop-only Side shadow is structurally retired only after an accepted complete App Server inventory excludes the child and three bounded targeted child reads return exact empty pages；waiting/Plan、confirmed App Server live、newer evidence and incomplete inventory fail closed to retention。The retirement removes the stale relation/shadow and lets the retained parent terminal evidence project again；it never uses age/TTL as terminal authority。Its diagnostic is limited to anonymous topology scope plus finite `inventory=complete / latestTurn=empty` facts。Semantic-only `side-topology-decision` and `parent-state-decision` diagnostics retain only a session-scoped hashed parent ref、finite counts、phase/unread/reason and limited Goal-reason counts；raw identity、title、content、path、Goal content、budget and usage never enter the sink.
- RAW-162 adds a process-private Codex Goal Evidence lane inside [preload/index.js](../../preload/index.js#L1). Cold inventory reads `thread/goal/get` under the existing concurrency bound；steady state consumes `thread/goal/updated` and `thread/goal/cleared`；a terminal candidate with unknown/stale evidence joins one per-thread single-flight reread before completion。The cache stores only finite status、updatedAt、freshness and a live causal sequence。RPC request baselines plus updatedAt reject late reads；transient failure/timeout retains the stable non-terminal phase as verifying，while method-not-found alone establishes process-level compatibility fallback。Goal-only changes force a private-evidence transaction even when the public Activity fingerprint is unchanged，then the matching Host draft and Branch Store still publish at most one task package。The Kernel records whether its retained non-terminal authority came from Goal or Turn，so cleared Goal releases a Goal-owned running phase，and a strictly newer Turn can supersede an old non-active Goal to open a new execution epoch。No Goal objective、raw identity、budget or usage crosses the Bridge、diagnostics or persistence boundary.
- [preload/index.js](../../preload/index.js#L1) 的 `onPluginEnter` 在 Renderer 未挂载时直接让 Kernel 消费静默任务入口；Host 已有精确 key 的热动作立即派发且不重新盘点/分类，只有 Host target/private mapping 缺失的冷/gap 动作才加入 provider-scoped tasks-only 解析，失败拒绝 partial jump。普通隐藏保留动态包，真实退出/功能关闭/Provider 变化才清理；包不落盘。Main Renderer 隐藏时 Preload 仍可直接把同一包推到 Float，quota、环境、完整库存和非任务 unread 沿独立通道运行。[codexController.ts](../../src/runtime/codexController.ts#L1) 的 card/input/cycle/Plan 动作只提交意图，不在派发前主动同步任务包。
- [utools-runtime-identity.mjs](../../scripts/utools-runtime-identity.mjs#L1) 对受管 Host 与 Renderer 输入生成确定性资产 ID。Main UI/Main Preload/Float UI/Float Preload 必须完成 Host、Renderer、Kernel 与 Package revision 的精确握手；任何旧子窗口 ASAR、旧 Preload 或新旧 UI 组合都 fail closed 为 `reload-required`。Preload 只在身份语义变化时记录匿名 `runtime-identity-handshake`，包含非私密实际/期望 artifact hash、Kernel/Package revision 与 `host-loaded/reload-required`。构建阶段只能形成 `artifact-ready`；uTools 真正加载同一资产并握手后才形成 `host-loaded`，进程启动时间不构成加载证据。这条边界不使用私有 uTools API，也不自动结束后台进程。
- [codexController.ts](../../src/runtime/codexController.ts#L1) accepts the single process package and owns UI in-flight presentation, but a Provider-only Codex `archived` result cannot delete a task.
