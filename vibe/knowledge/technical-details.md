## File Favorites Runtime

- Last verified: 2026-07-11.
- Runtime boundary: favorite UI emits action ids; [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1) resolves target kind and IDs in `explicit → frozen drawer → active-pane focus → visible selection` order before [src/platform/eypcPlatform.ts](../../src/platform/eypcPlatform.ts#L1) or [preload/index.js](../../preload/index.js#L1) is called.
- `FileActionResult` uses `success | dispatched | revealed-instead | failed`; a legacy boolean `true` is only `dispatched`. Errors use the bounded file error-code set, and browser development actions are disabled by `FileCapabilities` when the host cannot perform them.
- Open performs path preflight and prefers Electron `shell.openPath`, whose empty result confirms success. uTools void calls are dispatch-only. On macOS, failed open followed by successful reveal reports `revealed-instead`; the native fallback retains timeout and handler error codes.
- Path inspections use `lstat/stat/access` with bounded promises. If metadata reads succeed but access is denied, the Runtime keeps known type, symlink, size and modification time with `exists=true`; `ENOENT` alone clears existence. Missing/denied/offline paths remain in metadata, and inspection rejection becomes explicit `unknown/io-error` instead of an endless loading label.
- Directory reads are one-level, bounded and race-protected. Host display paths are preserved while selection, focus, duplicate marking and favorite matching use [favoritePathIdentityKey](../../src/domain/favorites.ts#L1). Resolvable file/folder links expose target-kind metadata without recursive reads; special or unresolved entries are filtered rather than coerced to `file`.
- Quick mode invalidates directory requests, clears selections/drawer/edit layers and focuses its first visible row. Full mode cycles only available `containers | items | directory` panes, clears inactive-pane row focus, issues a DOM focus request and implements the documented Escape recovery chain.
- One-step removal undo reinserts nodes at their original positions and merges removed collapse ids. It restores sanitized pane/focus/selection only when the current context still equals the automatic post-removal context, so later navigation wins.
- [ConfirmLayer.vue](../../src/components/ConfirmLayer.vue#L1) restores persistent triggers directly. When a confirmed mutation removes the trigger, it selects an ordered visible fallback supplied by [src/App.vue](../../src/App.vue#L1) and retries for a bounded number of animation frames while focus remains on `body`.
- At `<=720px`, the container side layer makes `visibility` immediate on open and delays it only on close. [FavoritesPage.vue](../../src/pages/FavoritesPage.vue#L1) can therefore focus the tree after render without racing the 160ms transform transition.
- uTools packaging keeps the root package ESM while [public/package.json](../../public/package.json#L1) declares the CommonJS scope. [utools-preload-assets.mjs](../../scripts/utools-preload-assets.mjs#L1) is the single manifest for main/float/action canonical, public and dist preload paths; [sync-utools-preloads.mjs](../../scripts/sync-utools-preloads.mjs#L1) updates public mirrors, [prepare-utools-runtime.mjs](../../scripts/prepare-utools-runtime.mjs#L1) prepares dist from the same manifest, and [validate-utools-runtime.mjs](../../scripts/validate-utools-runtime.mjs#L1) rejects source/public/dist drift and any JavaScript asset above 500 kB. [App.vue](../../src/App.vue#L1) lazy-loads all seven main tabs, while [vite.config.ts](../../vite.config.ts#L1) gives Vue, Markdown and icon dependencies stable vendor chunks; the 2026-07-31 production main chunk fell from 599.78 kB to 370.25 kB without raising Vite's warning threshold. Root [package.json](../../package.json#L1) exposes `pnpm run verify` as sync → full Vitest → semantic typecheck/production build/uTools validation, without starting a host or dev server. Reusable packaging/HMR contracts: CodeNote [development-runtime](../../../../../czz/CzzProj/CodeNote/DevelopRef/Multi-System-Use/uTools/development-runtime.md#L1) · [child-window-vite-hmr](../../../../../czz/CzzProj/CodeNote/DevelopRef/Multi-System-Use/uTools/child-window-vite-hmr.md#L1).
- Component behavior coverage uses [favoritesBehavior.test.ts](../../tests/ui/favoritesBehavior.test.ts#L1); domain/Runtime/platform matrices are in [favorites.test.ts](../../tests/domain/favorites.test.ts#L1), [action.test.ts](../../tests/runtime/action.test.ts#L1), [favoriteFileBridge.test.ts](../../tests/platform/favoriteFileBridge.test.ts#L1), and [eypcPlatform.test.ts](../../tests/platform/eypcPlatform.test.ts#L1).

## Codex App Server And Floating Surface

- Last verified baseline: 2026-07-20. RAW-056 implemented 2026-07-22 and remains unverified pending user acceptance.
- [preload/index.js](../../preload/index.js#L1) discovers a controlled Codex executable and starts `codex app-server --listen stdio://` from the user home directory. This connector owns quota/models/inventory/create/persistent archive. A separate macOS Codex Desktop private-IPC companion bridge owns live task/read authority and archive-refresh notification until Easy Agent replaces the interim providers. Ordinary snapshots use `account/rateLimits/read`, `account/read`, `config/read`, `model/list`, `thread/list` and bounded `thread/turns/list`; they do not read `auth.json` or use a private quota endpoint. App Server Turn views omit finite decisions, so interrupted/failed/inProgress rows may use the last 4 MiB of a real rollout under `CODEX_HOME/sessions` for unmatched exact `request_user_input`; completed rows progressively read `256 KiB / 1 MiB / 4 MiB` and accept only exact latest-Turn `item_completed + Plan`, cleared by a later `task_started`. The parsers publish no content/path/call identity. Unread arbitration is exact event/successful-open acknowledgement → refollow false → current parseable native membership/nonmembership → last successful Bridge-native observation during transient unavailability → weak snapshot fallback; new completion clears earlier false evidence. The open acknowledgement is preload-session-only, covers the parent and known Side Chats, emits anonymous `readStateOnly`, and never writes the native file or legacy receipt. An exact `turn/completed` without a usable Turn object resolves the mapped parent/query thread and runs immediate + `25/75/150/300/600/1000ms` latest-Turn reads within three seconds; it emits only confirmed anonymous completion and falls back to urgent inventory only on exhaustion. True archive uses `thread/read(includeTurns=false)` for fail-closed identity/status/recency validation. The dedicated new-thread path uses exact `thread/start`, optional `turn/start` and thread-only Deep Link; raw responses never cross the Renderer bridge.
- CLI discovery emits only safe source labels. A user may provide one absolute CLI location through the configuration action; preload validates it with the same native/Node-wrapper/Windows shim plan before persisting a separate local-plugin preference. Environment snapshots expose no path and manual entries fail explicitly rather than silently falling through. Without a manual entry, automatic discovery and the existing connector are retained as a possibly delayed data/action fallback; they never supply Input, ongoing or completed-unread authority.
- GUI hosts are not assumed to inherit terminal/NVM PATH. When a controlled candidate resolves to a JavaScript wrapper, the preload launches it through the verified sibling Node executable and prefixes only that command directory in the child environment. Startup stderr is reduced to a bounded in-memory classifier; renderer errors contain no raw stderr, command path or PATH value.
- First-launch environment inspection is a separate read-only phase. If the feature is enabled it runs once even while the active Tab is not Codex and the float is hidden; if disabled it waits until enable. It reports only platform/runtime-source/process/config/connection enums, a timestamp and a stable error code. macOS process detection reduces bounded `/bin/ps` output to an exact Codex basename; Windows reduces bounded system `tasklist.exe` CSV to exact `Codex.exe`. Config inspection checks existence/readability only for controlled `CODEX_HOME/config.toml` or default Codex Home and never reads content.
- [eypcPlatform.ts](../../src/platform/eypcPlatform.ts#L1) distinguishes a no-host browser fallback from a legacy desktop preload. When the desktop host still exposes `readSnapshot` but lacks additive `inspectEnvironment`, it infers macOS/Windows from navigator platform metadata but leaves CLI readiness pending. [codexController.ts](../../src/runtime/codexController.ts#L1) treats a successful read as stronger evidence, promotes detected/running/loaded/connected and uses a read generation to reject disable/re-enable and post-disposal results. Manual launch-path set/clear already returns the freshly inspected snapshot, which the Controller publishes directly without a redundant second scan. [codexEnvironmentPresentation.ts](../../src/domain/codexEnvironmentPresentation.ts#L1) owns the compatibility-pending predicate, banner, grid and launch help; [CodexPage.vue](../../src/pages/CodexPage.vue#L1) only renders that projection, so connected rows cannot coexist with an unsupported alert.
- Windows runtime discovery uses `path.win32` and controlled `%APPDATA%\\npm`, `%LOCALAPPDATA%`, `VOLTA_HOME`, `NVM_SYMLINK`, local and inherited-Path candidates. For `.cmd`/`.bat`, only the known adjacent `node_modules/@openai/codex/bin/codex.js` may be paired with a verified absolute Node runtime, or a verified bundled optional-dependency binary may be used. An unresolved shim returns `runtime-unavailable`; it is never direct-spawned and no general shell is introduced.
- GUI hosts are also not assumed to consume macOS PAC. When no explicit proxy environment exists, the preload reads bounded `scutil` output, fetches only an unauthenticated loopback `http` PAC with an absolute system client, and accepts only a single static `FindProxyForURL` return beginning with a loopback HTTP `PROXY`. It never evaluates PAC JavaScript; dynamic, remote, oversized or SOCKS-only shapes fail open to the existing launch path. Derived values are child-only and never leave preload memory.
- App Server results are allowlisted before crossing the preload boundary. Quota V2 keeps ordinary/Spark pool name/id plus actual percentage/reset/window, model catalog keeps display-safe text/input/default/family fields and a fingerprint, and config keeps model/reasoning/service tier. Host Snapshot V2 combines the allowlisted native project registry with complete `archived=false` pagination, anonymous project/task keys, native order, strict latest Turn timing, a source fingerprint and short-lived action aliases. Desktop full snapshots may be received transiently for protocol projection, but raw thread/turn IDs, roots/paths, cursors, native state, bodies and item payloads remain preload-only and clear with session generation.
- [codexController.ts](../../src/runtime/codexController.ts#L1) separates environment, quota/config and verified inventory lanes. Quota uses `quotaRefreshSeconds` (default 300) and full inventory uses `taskRefreshSeconds` (default 15); both normalize to integer `0–86400`, with zero manual-only, and the shared scheduler converts each independently to milliseconds. Verified task/project inventory plus Activity subscriptions remain active for the entire enabled-feature lifetime, including other main Tabs and a hidden Float; quota/config remain surface-owned. Feature/inbox disable and disposal clear derived state and reject late work. Missing-key quarantine, 50/200ms structural coalescing and in-flight replay remain independent from task-state resolution. Activity Delta now carries finite activity/Turn provenance. - Runtime shortcut context must treat open draft-history popovers/editors as command-owned layers before trusting DOM focus. This prevents stale `mqtt-publish-editor` focus from stealing `Space`, drawer, edit, or delete commands.
- Connection and subscription rails are runtime-owned row targets. Connection state includes selected config ids; subscription selection uses `MqttRecordSelection.kind = "subscription"` so detail/action drawers can target topics without pretending they are message records.
- Connection group rows use `MqttRecordSelection.kind = "connection-group"` and can focus, show detail/actions, edit, delete, collapse, expand, and drag/drop without switching the active MQTT connection config.
- Deleting a connection group removes only group metadata. Direct child groups/configs are promoted to the deleted group's parent so existing connections are not lost.
- Runtime adds `mqttTargetKind` to shortcut context so connection-pane `F2` and `Shift+F2` dispatch to config commands for config rows and group commands for group rows.
- Connection rail actions include movement, multi-select, endpoint copy, focused/selected delete, detail drawer, action drawer, and right-click entry. Subscription rail actions include movement, multi-select, topic copy, use-as-publish-topic, focused/selected delete, detail drawer, action drawer, and right-click entry.
- Connection-config editor focus is a generated matrix instead of a fixed field list, so `Tab` / `Shift+Tab` traverses per-subscription alias/topic/color rows, publish-topic rows, MQTT option fields, and storage options.
