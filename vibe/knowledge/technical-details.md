## File Favorites Runtime

- Last verified: 2026-07-11.
- Runtime boundary: favorite UI emits action ids; [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1) resolves target kind and IDs in `explicit → frozen drawer → active-pane focus → visible selection` order before [src/platform/eypcPlatform.ts](../../src/platform/eypcPlatform.ts#L1) or [preload/index.js](../../preload/index.js#L1) is called.
- `FileActionResult` uses `success | dispatched | revealed-instead | failed`; a legacy boolean `true` is only `dispatched`. Errors use the bounded file error-code set, and browser development actions are disabled by `FileCapabilities` when the host cannot perform them.
- Open performs path preflight and prefers Electron `shell.openPath`, whose empty result confirms success. uTools void calls are dispatch-only. On macOS, failed open followed by successful reveal reports `revealed-instead`; the native fallback retains timeout and handler error codes.
- Path inspections use `lstat/stat/access` with bounded promises. If metadata reads succeed but access is denied, the Runtime keeps known type, symlink, size and modification time with `exists=true`; `ENOENT` alone clears existence. Missing/denied/offline paths remain in metadata, and inspection rejection becomes explicit `unknown/io-error` instead of an endless loading label.
- Directory reads are one-level, bounded and race-protected. Host display paths are preserved while selection, focus, duplicate marking and favorite matching use [favoritePathIdentityKey](../../src/domain/favorites.ts#L1). Resolvable file/folder links expose target-kind metadata without recursive reads; special or unresolved entries are filtered rather than coerced to `file`.
- Quick mode invalidates directory requests, clears selections/drawer/edit layers and focuses its first visible row. Full mode cycles only available `containers | items | directory` panes, clears inactive-pane row focus, issues a DOM focus request and implements the documented Escape recovery chain.
- One-step removal undo reinserts nodes at their original positions and merges removed collapse ids. It restores sanitized pane/focus/selection only when the current context still equals the automatic post-removal context, so later navigation wins.
- [ConfirmLayer.vue](../../src/components/ConfirmLayer.vue#L1) restores persistent triggers directly. When a confirmed mutation removes the trigger, it selects an ordered visible fallback supplied by [src/App.vue](../../src/App.vue#L1) and retries for a bounded number of animation frames while focus remains on `body`.
- At `<=720px`, the container side layer makes `visibility` immediate on open and delays it only on close. [FavoritesPage.vue](../../src/pages/FavoritesPage.vue#L1) can therefore focus the tree after render without racing the 160ms transform transition.
- uTools packaging keeps the root package ESM while [public/package.json](../../public/package.json#L1) declares the CommonJS scope. [prepare-utools-runtime.mjs](../../scripts/prepare-utools-runtime.mjs#L1) synchronizes the canonical preload and [validate-utools-runtime.mjs](../../scripts/validate-utools-runtime.mjs#L1) rejects source/public/dist drift. Reusable packaging/HMR contracts: CodeNote [development-runtime](../../../../../czz/CzzProj/CodeNote/DevelopRef/Multi-System-Use/uTools/development-runtime.md#L1) · [child-window-vite-hmr](../../../../../czz/CzzProj/CodeNote/DevelopRef/Multi-System-Use/uTools/child-window-vite-hmr.md#L1).
- Component behavior coverage uses [favoritesBehavior.test.ts](../../tests/ui/favoritesBehavior.test.ts#L1); domain/Runtime/platform matrices are in [favorites.test.ts](../../tests/domain/favorites.test.ts#L1), [action.test.ts](../../tests/runtime/action.test.ts#L1), [favoriteFileBridge.test.ts](../../tests/platform/favoriteFileBridge.test.ts#L1), and [eypcPlatform.test.ts](../../tests/platform/eypcPlatform.test.ts#L1).

## Codex App Server And Floating Surface

- Last verified baseline: 2026-07-20. RAW-056 implemented 2026-07-22 and remains unverified pending user acceptance.
- [preload/index.js](../../preload/index.js#L1) discovers a controlled Codex executable and starts `codex app-server --listen stdio://` from the user home directory. This connector owns quota/models/inventory/create/persistent archive. A separate macOS Codex Desktop private-IPC companion bridge owns live task/read authority and archive-refresh notification until Easy Agent replaces the interim providers. Ordinary snapshots use `account/rateLimits/read`, `account/read`, `config/read`, `model/list`, `thread/list` and bounded `thread/turns/list`; they do not read `auth.json` or use a private quota endpoint. True archive uses `thread/read(includeTurns=false)` for fail-closed identity/status/recency validation. The dedicated new-thread path uses exact `thread/start`, optional `turn/start` and thread-only Deep Link; raw responses never cross the Renderer bridge.
- CLI discovery emits only safe source labels. A user may provide one absolute CLI location through the configuration action; preload validates it with the same native/Node-wrapper/Windows shim plan before persisting a separate local-plugin preference. Environment snapshots expose no path and manual entries fail explicitly rather than silently falling through. Without a manual entry, automatic discovery and the existing connector are retained as a possibly delayed data/action fallback; they never supply Input, ongoing or completed-unread authority.
- GUI hosts are not assumed to inherit terminal/NVM PATH. When a controlled candidate resolves to a JavaScript wrapper, the preload launches it through the verified sibling Node executable and prefixes only that command directory in the child environment. Startup stderr is reduced to a bounded in-memory classifier; renderer errors contain no raw stderr, command path or PATH value.
- First-launch environment inspection is a separate read-only phase. If the feature is enabled it runs once even while the active Tab is not Codex and the float is hidden; if disabled it waits until enable. It reports only platform/runtime-source/process/config/connection enums, a timestamp and a stable error code. macOS process detection reduces bounded `/bin/ps` output to an exact Codex basename; Windows reduces bounded system `tasklist.exe` CSV to exact `Codex.exe`. Config inspection checks existence/readability only for controlled `CODEX_HOME/config.toml` or default Codex Home and never reads content.
- [eypcPlatform.ts](../../src/platform/eypcPlatform.ts#L1) distinguishes a no-host browser fallback from a legacy desktop preload. When the desktop host still exposes `readSnapshot` but lacks additive `inspectEnvironment`, it infers macOS/Windows from navigator platform metadata but leaves CLI readiness pending. [codexController.ts](../../src/runtime/codexController.ts#L1) treats a successful read as stronger evidence, promotes detected/running/loaded/connected and uses a read generation to reject disable/re-enable and post-disposal results; [CodexPage.vue](../../src/pages/CodexPage.vue#L1) shows a neutral verification state before the first round-trip and prevents connected rows from coexisting with an unsupported alert.
- Windows runtime discovery uses `path.win32` and controlled `%APPDATA%\\npm`, `%LOCALAPPDATA%`, `VOLTA_HOME`, `NVM_SYMLINK`, local and inherited-Path candidates. For `.cmd`/`.bat`, only the known adjacent `node_modules/@openai/codex/bin/codex.js` may be paired with a verified absolute Node runtime, or a verified bundled optional-dependency binary may be used. An unresolved shim returns `runtime-unavailable`; it is never direct-spawned and no general shell is introduced.
- GUI hosts are also not assumed to consume macOS PAC. When no explicit proxy environment exists, the preload reads bounded `scutil` output, fetches only an unauthenticated loopback `http` PAC with an absolute system client, and accepts only a single static `FindProxyForURL` return beginning with a loopback HTTP `PROXY`. It never evaluates PAC JavaScript; dynamic, remote, oversized or SOCKS-only shapes fail open to the existing launch path. Derived values are child-only and never leave preload memory.
- App Server results are allowlisted before crossing the preload boundary. Quota V2 keeps ordinary/Spark pool name/id plus actual percentage/reset/window, model catalog keeps display-safe text/input/default/family fields and a fingerprint, and config keeps model/reasoning/service tier. Host Snapshot V2 combines the allowlisted native project registry with complete `archived=false` pagination, anonymous project/task keys, native order, strict latest Turn timing, a source fingerprint and short-lived action aliases. Desktop full snapshots may be received transiently for protocol projection, but raw thread/turn IDs, roots/paths, cursors, native state, bodies and item payloads remain preload-only and clear with session generation.
- [codexController.ts](../../src/runtime/codexController.ts#L1) separates environment, quota/config and verified inventory lanes. Missing-key quarantine, 50/200ms structural coalescing and in-flight replay remain independent from task-state resolution. Activity Delta now carries finite activity/Turn provenance. Controller merges Turn evidence monotonically, rejects only terminal evidence already present before the active exit, and clears the exit baseline as soon as a terminal outcome survives that guard. A real activity patch opens a new epoch; exact/targeted/corroborated completion closes it immediately. `desktopActiveSince` is ignored for semantic ordering and `completionPresentationDelayMs` is absent from the normalized runtime settings shape. Polling remains active-surface-owned and disposal/activation generations clear late work and in-memory candidates.
- Conversation projection V3 applies the inclusive rolling 1–365 day window and retains `all / inputRequired / ongoing / stopped / hidden / completed / projects` as projection data, but exposes only four visible tabs `ongoing / completed / hidden / projects`. Eligibility uses the evidence-backed latest Turn `max(startedAt, completedAt)` while still requiring `startedAt`; exact Desktop request state is authoritative for input/approval, while ordinary active accepts `desktop-live` or exact-event `app-server-live`; `updatedAt` never substitutes for Turn evidence. Projection priority is live active → latest-Turn completed → latest-Turn failed/interrupted with exact live idle or bridge not-running → ongoing. The explicit stop maps to `stopped/stopped/blocked-stopped`; bridge failed/incompatible/connecting, systemError, notLoaded, connector/authority loss, missing Turn/live idle and timeout remain `ongoing/running/blocked-active`. `unknownCount/attentionCount` are zero, compact counters exclude stopped, and no state becomes terminal through elapsed time. Every source task array sorts strictly by latest Turn `startedAt` descending and anonymous key. Native/local pin sets are resolved onto every task and project card before project grouping.
- Project ownership precedence is native assignment, native projectless→Chats, then deepest valid registered project root. Other rows are excluded as removed/unregistered. The project view mirrors native `Pinned / Projects / Chats`, orders pins as EyPc conversations → native conversations → EyPc projects → native projects, places Chats children immediately after their title, and never duplicates a pinned task in its project.

Pin toggles republish immediately, project hide affects only grouping, and search/selection/focus/action aliases/task arrays remain memory-only.
- `codex.task.archive` is exposed only for a latest Turn with explicit completed evidence and accepts an exact short-lived alias plus expected completed revision, Turn and source fingerprint. Preload rereads native fingerprint, identity, status, recency and newest Turn; desktop-live active/inProgress/interrupted/new-version/malformed evidence fails closed. It removes the row only after `thread/archive` and complete false-absence/true-presence verification, then dispatches `thread-archived` v2 to a connected Desktop bridge. Dispatch failure is reported separately and does not undo verified persistence. Project archive skips non-completed work and repeats the same sequence for remaining completed items.

A replacement updates the current locator/native reference and at most four prior verified titles only after native activation succeeds; weak/tied/multiple candidates stay manual. Capability revision is `wj18-cg-title-source`; Space/revision/rebind/partial-refresh faults become stable sanitized blocking diagnostics. - Diagnostics UI: [src/pages/WindowsPage.vue](../../src/pages/WindowsPage.vue#L1) is list-first: compact toolbar, left collapsible equal-height slot rail (empty-slot picker; assigned focus / Shift-clear / context configure), and right collapsible log rail for activation diagnostics plus development operation traces so logs do not consume main list height. Blocking diagnostics auto-expand the log rail. Diagnostics show only time, slot/manual entry, platform, stage, stable code, level, and sanitized explanation. In development builds the short blocking panel is suppressed when the operation-trace panel is present; the trace shows numbered `stage=outcome[:detail]` chips (including macOS `space` SkyLight switch detail), a one-line copyable plain-text summary, and `windows.operation.traces.clear`. Blocking records use alert semantics in production-only diagnostics; accepted closed targets use status semantics; `windows.activation.diagnostics.clear` clears only the current Runtime session. Installed builds render neither the development trace nor any raw host detail. Keyboard: `ArrowUp`/`ArrowDown` list move, `ArrowRight` open actions, `Ctrl+1`…`Ctrl+0` assign focused row to slots. The action layer differentiates EyPc “列表置顶” from Windows “页面置顶”.
