## File Favorites Runtime

- Last verified: 2026-07-11.
- Runtime boundary: favorite UI emits action ids; [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1) resolves target kind and IDs in `explicit → frozen drawer → active-pane focus → visible selection` order before [src/platform/eypcPlatform.ts](../../src/platform/eypcPlatform.ts#L1) or [preload/index.js](../../preload/index.js#L1) is called.
- `FileActionResult` uses `success | dispatched | revealed-instead | failed`; a legacy boolean `true` is only `dispatched`. Errors use the bounded file error-code set, and browser development actions are disabled by `FileCapabilities` when the host cannot perform them.
- Open performs path preflight and prefers Electron `shell.openPath`, whose empty result confirms success. uTools void calls are dispatch-only. On macOS, failed open followed by successful reveal reports `revealed-instead`; the native fallback retains timeout and handler error codes.
- Path inspections use `lstat/stat/access` with bounded promises. If metadata reads succeed but access is denied, the Runtime keeps known type, symlink, size and modification time with `exists=true`; `ENOENT` alone clears existence. Missing/denied/offline paths remain in metadata, and inspection rejection becomes explicit `unknown/io-error` instead of an endless loading label.
- Directory reads are one-level, bounded and race-protected. Host display paths are preserved while selection, focus, duplicate marking and favorite matching use [favoritePathIdentityKey](../../src/domain/favorites.ts#L1). Resolvable file/folder links expose target-kind metadata without recursive reads; special or unresolved entries are filtered rather than coerced to `file`.
- Quick mode invalidates directory requests, clears selections/drawer/edit layers and focuses its first visible row. Full mode cycles only available `containers | items | directory` panes, clears inactive-pane row focus, issues a DOM focus request and implements the documented Escape recovery chain.
- One-step removal undo reinserts nodes at their original positions and merges removed collapse ids. It restores sanitized pane/focus/selection only when the current context still equals the automatic post-removal context, so later navigation wins.
- [ConfirmLayer.vue](../../src/components/ConfirmLayer.vue#L1) restores persistent triggers directly. When a confirmed mutation removes the trigger, it selects an ordered visible fallback supplied by [src/App.vue](../../src/App.vue#L1) and retries for a bounded number of animation frames while focus remains on `body`.
- At `<=720px`, the container side layer makes `visibility` immediate on open and delays it only on close. [FavoritesPage.vue](../../src/pages/FavoritesPage.vue#L1) can therefore focus the tree after render without racing the 160ms transform transition.
- uTools packaging keeps the root package ESM while [public/package.json](../../public/package.json#L1) declares the CommonJS scope. [prepare-utools-runtime.mjs](../../scripts/prepare-utools-runtime.mjs#L1) synchronizes the canonical preload and [validate-utools-runtime.mjs](../../scripts/validate-utools-runtime.mjs#L1) rejects source/public/dist drift.
- Component behavior coverage uses [favoritesBehavior.test.ts](../../tests/ui/favoritesBehavior.test.ts#L1); domain/Runtime/platform matrices are in [favorites.test.ts](../../tests/domain/favorites.test.ts#L1), [action.test.ts](../../tests/runtime/action.test.ts#L1), [favoriteFileBridge.test.ts](../../tests/platform/favoriteFileBridge.test.ts#L1), and [eypcPlatform.test.ts](../../tests/platform/eypcPlatform.test.ts#L1).
- Update trigger: change this record when the graph/path contract, file result/capability bridge, target priority, Quick transition, directory request model, removal undo, preload packaging, or favorite focus/restore model changes.

## Codex App Server And Floating Surface

- Last verified: 2026-07-20.
- [preload/index.js](../../preload/index.js#L1) discovers a controlled Codex executable and starts `codex app-server --listen stdio://` from the user home directory. Ordinary snapshots use `account/rateLimits/read`, `account/read`, `config/read`, `model/list`, `thread/list` and bounded `thread/turns/list`; they do not read `auth.json` or use a private quota endpoint. True archive uses `thread/read(includeTurns=false)` for fail-closed identity/status/recency validation. The dedicated new-thread path uses exact `thread/start`, optional `turn/start` and thread-only Deep Link; raw responses never cross the bridge.
- GUI hosts are not assumed to inherit terminal/NVM PATH. When a controlled candidate resolves to a JavaScript wrapper, the preload launches it through the verified sibling Node executable and prefixes only that command directory in the child environment. Startup stderr is reduced to a bounded in-memory classifier; renderer errors contain no raw stderr, command path or PATH value.
- First-launch environment inspection is a separate read-only phase. If the feature is enabled it runs once even while the active Tab is not Codex and the float is hidden; if disabled it waits until enable. It reports only platform/runtime-source/process/config/connection enums, a timestamp and a stable error code. macOS process detection reduces bounded `/bin/ps` output to an exact Codex basename; Windows reduces bounded system `tasklist.exe` CSV to exact `Codex.exe`. Config inspection checks existence/readability only for controlled `CODEX_HOME/config.toml` or default Codex Home and never reads content.
- [eypcPlatform.ts](../../src/platform/eypcPlatform.ts#L1) distinguishes a no-host browser fallback from a legacy desktop preload. When the desktop host still exposes `readSnapshot` but lacks additive `inspectEnvironment`, it infers macOS/Windows from navigator platform metadata but leaves CLI readiness pending. [codexController.ts](../../src/runtime/codexController.ts#L1) treats a successful read as stronger evidence, promotes detected/running/loaded/connected and uses a read generation to reject disable/re-enable and post-disposal results; [CodexPage.vue](../../src/pages/CodexPage.vue#L1) shows a neutral verification state before the first round-trip and prevents connected rows from coexisting with an unsupported alert.
- Windows runtime discovery uses `path.win32` and controlled `%APPDATA%\\npm`, `%LOCALAPPDATA%`, `VOLTA_HOME`, `NVM_SYMLINK`, local and inherited-Path candidates. For `.cmd`/`.bat`, only the known adjacent `node_modules/@openai/codex/bin/codex.js` may be paired with a verified absolute Node runtime, or a verified bundled optional-dependency binary may be used. An unresolved shim returns `runtime-unavailable`; it is never direct-spawned and no general shell is introduced.
- GUI hosts are also not assumed to consume macOS PAC. When no explicit proxy environment exists, the preload reads bounded `scutil` output, fetches only an unauthenticated loopback `http` PAC with an absolute system client, and accepts only a single static `FindProxyForURL` return beginning with a loopback HTTP `PROXY`. It never evaluates PAC JavaScript; dynamic, remote, oversized or SOCKS-only shapes fail open to the existing launch path. Derived values are child-only and never leave preload memory.
- App Server results are allowlisted before crossing the preload boundary. Quota V2 keeps ordinary/Spark pool name/id plus actual percentage/reset/window, model catalog keeps display-safe text/input/default/family fields and a fingerprint, and config keeps model/reasoning/service tier. Host Snapshot V2 combines the allowlisted native project registry with complete `archived=false` pagination, anonymous project/task keys, native order, strict latest Turn timing, a source fingerprint and short-lived action aliases. Raw thread/turn IDs, roots/paths, cursors, native state and item payloads remain preload-only and clear with session generation.
- [codexController.ts](../../src/runtime/codexController.ts#L1) separates one-time environment inspection from App Server data. Quota/config and inventory lanes use independent structured results; inventory publishes only when native-state, pagination, assignment and Turn-time completeness are verified. A source change retries the full scan once; later failure preserves only the previous verified snapshot as stale. Polling remains active-surface-owned and disposal/activation generations reject late results.
- Conversation projection V3 applies the inclusive rolling 1–365 day window and creates `all / ongoing / hidden / completed / projects`. Only exact thread `active` is authoritative live; latest Turn completed/failed/interrupted preserves its persisted result, while systemError/notLoaded/timeout remains explicit. Every task array sorts strictly by latest Turn `startedAt` descending and anonymous key; there is no `updatedAt` fallback.
- Project ownership precedence is native assignment, native projectless→Chats, then deepest valid registered project root. Other rows are excluded as removed/unregistered. The project view mirrors native `Pinned / Projects / Chats`, preserves empty projects, appends EyPc-local pins after native pins and never duplicates a task.
- `codex.task.open` never changes upstream task state; a successful open may advance only the current EyPc completed-unread watermark. `codex.task.hide/restore`, aliases, local pins and “从 EyPc 移除” use anonymous identities and only modify EyPc local metadata; they never write Codex native state. Search, selection, focus, action aliases and task arrays remain memory-only.
- `codex.task.archive` accepts an exact short-lived alias plus expected version, latest Turn and source fingerprint. Preload rereads native fingerprint, identity, status, recency and newest Turn; active/inProgress/new-version/malformed evidence fails closed. It removes the row only after `thread/archive` and complete false-absence/true-presence verification. Project archive scans all project history outside the display window, skips active rows, uses batches of 20/concurrency 2 and retains per-item failures.
- Task timing is evidence-only. Latest question time comes only from latest Turn `startedAt` and drives every task sort; creation/completion/status metadata may be displayed but never infer state. The Codex child never uses native `title` or the main Tooltip layer and has no ordinary hover detail; pure Shift preview renders only the explicit privacy whitelist in a non-focus-stealing, viewport-clamped overlay.
- Compact quota selection is centralized in [codexPresentation.ts](../../src/domain/codexPresentation.ts#L1): ordinary 5-hour positive quota, ordinary weekly positive quota, then the highest positive Spark pool. Spark renders `S` and its own weekly ring; missing 5-hour/weekly windows are never fabricated or treated as zero. [codexNewThread.ts](../../src/domain/codexNewThread.ts#L1) separately applies the stricter model rule that any actually returned ordinary zero window selects the highest available Spark.
- Paired-skin tokens are resolved by [codexAppearance.ts](../../src/domain/codexAppearance.ts#L1). [CodexWaterBall.vue](../../src/components/CodexWaterBall.vue#L1) is shared by preview and float, uses horizontal repeating layers plus refractive highlights without liquid rotation, and renders the actual Weekly ring. Reduced motion stops all wave movement.
- The true child window uses [float.html](../../float.html#L1), [preload/float.js](../../preload/float.js#L1), [FloatApp.vue](../../src/FloatApp.vue#L1) and [float.css](../../src/styles/float.css#L1). It does not mount `OperationTooltipLayer`. In compact water mode the surface's real client rectangle defines a midpoint: upper-half hover and all counter hover are inert, lower-half pointer entry/movement requests expansion, touch hover is ignored, and explicit click/keyboard activation remains intact. The card skin retains whole-surface hover expansion while its sibling counters keep direct event ownership. Project rows expose only `＋`; task rows single-click select/focus and double-click/Enter open, while all operations enter the synchronized drawer. Space advances only after adding selection. Two visible selections summon an absolute top/bottom avoiding batch toolbar without row movement. The child locally owns composer/model/Quick Jump/Shift-preview/inline/drawer/detail layers, focus restoration and Escape LIFO; pointer/focus departure collapses after about `100ms` unless a focusable transient layer, resize or confirmation defers it.
- The composer freezes [codexNewThread.ts](../../src/domain/codexNewThread.ts#L1) output at open time, uses native textarea/dictation and traps Tab locally. Its transient bridge sends only hashed project context, fingerprints, model ID and prompt. Preload resolves cwd/raw identity, disables provider model fallback, validates top-level actual model/cwd, cleans a failed zero-turn thread, and never places the prompt in generic actions/snapshots/logs/storage/Deep Links/clipboard.
- The activity lane keeps raw IDs in preload only. App Server `thread/status/changed` frames are converted through the verified anonymous inventory and published immediately; the 200ms fallback uses complete `archived=false` list pagination without Turn/body reads. Controller enforces single-flight, applies anonymous status deltas, backs off after repeated failures and routes inventory changes into the full fingerprinted snapshot path.
- The six-tab Renderer exposes input-required as an additive V3 projection, keeps `ongoing` as the persisted ID for the renamed dynamic Tab, and groups dynamic rows as input/current/unread. Completed-unread is a local completion-revision watermark: only a successful task open advances it.
- Window geometry is pure-tested in [floatWindow.ts](../../src/domain/floatWindow.ts#L1) and [codexFloatWindowBridge.test.ts](../../tests/platform/codexFloatWindowBridge.test.ts#L1), including negative displays, four-edge snap, resize end/cancel, exact-display restore, stale-display recent fallback and work areas smaller than the normal minimum. Compact hosts remain fixed at 104×104 water and 166×92 card. Expanded auto size is 360×280–460; manual size is at least 340×280 and at most the current work area minus 12px margins. The custom handle is available whenever expanded, sends only screen coordinates/corner, and the parent alone calls `setBounds`. On macOS the parent also reapplies `floating` always-on-top plus `setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true })` after creation, sync, geometry reset and cross-display drag; settings receives only booleans and `checkedAt`.
- Visibility has one Runtime owner: `codex.float.toggle`. The app keybinding profile maps `Command+Option+Q` on macOS or `Ctrl+Alt+Q` on Windows across Tabs and ordinary text inputs. [plugin.json](../../public/plugin.json#L1) adds a static `eypc-codex-toggle` feature with `mainHide: true` for background/system-global invocation. uTools does not expose binding state, so the configuration page calls `redirectHotKeySetting` for the exact command label and never claims automatic registration.
- Bridge privacy/lifecycle/recovery/archive coverage is in [codexAppServerBridge.test.ts](../../tests/platform/codexAppServerBridge.test.ts#L1); activation, split-lane isolation, revision targeting, hidden open and geometry are in [codexController.test.ts](../../tests/runtime/codexController.test.ts#L1); projection/receipt behavior is in [codex.test.ts](../../tests/domain/codex.test.ts#L1); float interaction/accessibility is in [codexCompanion.test.ts](../../tests/ui/codexCompanion.test.ts#L1). Archived, unregistered-project, non-conversation and out-of-window rows are absent; local metadata never manufactures placeholders.

- Editing-surface ancestors do not hide command buttons or explicit shortcut targets; only editable DOM itself blocks global Quick Jump.
- `role="textbox"` is editable in [src/runtime/keyboardEvent.ts](../../src/runtime/keyboardEvent.ts#L1), so global non-edit shortcuts cannot steal text entry from ARIA textboxes.

## MQTT Workbench Runtime

- Last verified: 2026-06-27.
- Runtime source: [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1).
- Runtime projects active pane, active record list, record search, template/history rows, draft-history rows, MQTT connection tree rows, focus target, drawer targets, preview state, storage status, layout prefs, and view prefs.
- Ordinary messages and outgoing history sort newest first by `timestamp`; publish draft history sorts by `updatedAt`; templates sort by `MqttPublishTemplate.operatedAt` with `updatedAt` / `createdAt` fallback.
- Template operation time updates on save/edit/rename/apply/direct-send/repeat-send and does not update on focus, preview, detail, or menu open.
- Publish editor replacement archives the previous meaningful draft before applying a message/template/history/draft when the replacement differs. Manual draft save is `Ctrl+Shift+H`.
- Runtime shortcut context must treat open draft-history popovers/editors as command-owned layers before trusting DOM focus. This prevents stale `mqtt-publish-editor` focus from stealing `Space`, drawer, edit, or delete commands.
- Connection and subscription rails are runtime-owned row targets. Connection state includes selected config ids; subscription selection uses `MqttRecordSelection.kind = "subscription"` so detail/action drawers can target topics without pretending they are message records.
- Connection group rows use `MqttRecordSelection.kind = "connection-group"` and can focus, show detail/actions, edit, delete, collapse, expand, and drag/drop without switching the active MQTT connection config.
- Deleting a connection group removes only group metadata. Direct child groups/configs are promoted to the deleted group's parent so existing connections are not lost.
- Runtime adds `mqttTargetKind` to shortcut context so connection-pane `F2` and `Shift+F2` dispatch to config commands for config rows and group commands for group rows.
- Connection rail actions include movement, multi-select, endpoint copy, focused/selected delete, detail drawer, action drawer, and right-click entry. Subscription rail actions include movement, multi-select, topic copy, use-as-publish-topic, focused/selected delete, detail drawer, action drawer, and right-click entry.
- Connection-config editor focus is a generated matrix instead of a fixed field list, so `Tab` / `Shift+Tab` traverses per-subscription alias/topic/color rows, publish-topic rows, MQTT option fields, and storage options.

Config rows keep `F2` / `Shift+F2` for config edit/rename. `Ctrl+G` is also used by ports grouping and remains valid because keybindings are tab/context scoped.
- MQTT connection create shortcuts carry pane/panel/input-role context from [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1) into action dispatch. Parent inference for `Ctrl+G` / `Ctrl+N` uses explicit row args first, then `mqtt-connections` row focus, and otherwise creates root-level targets for connection search, blank rail, or other non-edit MQTT panes while the rail is expanded.
- Connection group editor focus owns `Ctrl+S`, `Ctrl+Enter`, `Tab`, `Shift+Tab`, and `Escape`.
- Subscription rail focus owns `Space`, `Ctrl+C`, `Delete`, `Backspace`, `Ctrl+Delete`, `Ctrl+Backspace`, `Ctrl+Left`, `Ctrl+Right`, `Enter` topic filter, and `Ctrl+Enter` use-as-publish-topic.
- Managed subscription/config/publish-topic editor rows use `ArrowUp` / `ArrowDown` for same-field row movement and `Ctrl+Delete` / `Ctrl+Backspace` for row deletion while plain text deletion remains native.
- Publish topic/payload editing intentionally does not own `Ctrl+Left` / `Ctrl+Right`; those chords remain native host text navigation. Publish options are opened by their button and close through `Escape` or outside pointerdown.
- Ordinary draft-history edit updates in [src/runtime/appRuntime.ts](../../src/runtime/appRuntime.ts#L1) must not request focus; focus requests belong to editor open and field-cycle commands.
