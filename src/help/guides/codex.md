# Codex

额度悬浮球与任务收件箱：在独立 Tab 配置外观与快捷方式，用桌面悬浮窗查看额度与近期任务状态，并支持只读打开 Codex 会话相关动作。

**默认状态：** 启用。首次启用后会做隐私最小化的环境检测（即使当时未打开 Codex Tab）。

## 入口

- 主窗口 **Codex** Tab
- uTools：`eypc-codex` 及相关全局功能（显示/隐藏悬浮球、直接展开卡片、待输入、已完成未读、上一个/下一个任务等）
- 插件内默认：`Ctrl+Alt+Q`（macOS 常为 `Command+Option+Q`）切换悬浮球；`Ctrl+Alt+Enter` 显示并展开卡片
- **Action Runner / Environment Action 槽 1–5**：都可在 Codex「快捷方式」里点「去设置」，到 uTools 全局功能绑定系统级快捷键；Runner 入口只展开工作台，槽位入口会展开、定位并执行

## 配置页分区

顶部导航（同一时间只渲染当前分区）：

1. **快捷方式** — 打开 uTools 绑定页或执行入口；**不读取、不回显**宿主当前快捷键绑定
2. **任务** — 任务列表展示相关选项（滚动窗口天数、动态小时数与完整校对秒数等）
3. **水球** — 紧凑悬浮球外观与读数
4. **卡片** — 展开面板主题（与水球配色独立）
5. **运行** — 环境诊断、连接状态、额度刷新秒数，以及 **接入来源**（Claude Code 开关、事件钩子注册、空闲额度补读）

说明性细节多用可聚焦的「i」提示，避免整页永久展开大段说明。

## 悬浮球与展开卡片

- 紧凑水球：显示额度读数与角标计数（待输入 / 进行中相关 / 已完成未读等；为 0 的角标会隐藏，超过 99 显示 `99+`）
- 同时接入 Codex 与 Claude 时，水球外圈进度表示 Codex 周额度、球心百分比表示 Claude 剩余额度并在下方标注来源；只接入其中一方时，该方独占整个水球，读数含义与单接入时完全一致
- 上半可点计数区、下半拖动区等分区以当前界面为准；展开后进入任务卡片
- 展开卡片内任务 Tab：**动态 / 已完成 / 已隐藏 / 项目**
- 额度后直接进入来源状态与任务内容；展开卡**不显示** Actions/Environment 卡槽、选择层或 Setup 提示
- 额度区是**一行**（固定 `min-height: 30px`），无论接入几个来源都不增减行数：每个读数是一个短标 + 百分比的小块（`5h` / `周`，Spark 前缀 `S`），同时接入两个来源时中间有分隔线与 `Claude` 平台标
  - 悬停 200ms 才显示完整含义与重置时间（`Codex · 5 小时限额 · 3 小时后重置`；只有一个来源时省略平台前缀），读屏用户不依赖悬停也能读到同样的完整文本
  - 每个来源的颜色是展开卡主题里可配置的 token（配置页「卡片」分区 → 额度读数），默认按主题自动取一个与健康色区分度足够、且对卡片底色对比度达标的色相
  - 浮窗很窄时先隐藏 `Claude` 平台标（颜色与分隔线保留），读数一个都不会丢；系统强制高对比度模式下平台色失效、平台标重新出现
  - 额度块不参与键盘焦点顺序
- 点击其它位置、指针/焦点离开时约 220ms 自动收回水球；编辑器、详情/抽屉、Quick Jump、预览或调整尺寸期间会暂缓
- 外观：内置多套主题；水球与展开卡片可分别配置；对比度不合法的配色会被限制

## Environment Action

- **独立 Runner：** Environment Action 不出现在 Codex Float 内。打开 `Action 执行工作台` 后，左侧按项目组织 Action；单 Environment 省略中间层，多 Environment 显示 `项目 → Environment → Action`
- **执行记录：** 右侧显示所选 Action 的实时脱敏输出、时间戳及完整项目/Environment/Action 归属；新执行自动展开并把上一轮压成一行，结束记录可手动归档和恢复
- **窗口：** 自绘标题栏支持拖动、四角缩放、置顶与隐藏；关闭按钮或 `Command/Ctrl+W` 只隐藏，不停止正在运行的 Action。`F` / `Shift+F` 可跳转当前可见操作
- **目标：** Controller 先使用 Codex 配置里的 **Action 默认项目**，未配置时回退到当前置顶/最近项目候选；Float 不另存项目或 Environment 选择状态。Runner 会先显示加载/修复消息，再在后台完成一次 Action-only 目标校验
- **全局快捷键：** Codex「快捷方式」可分别为 Runner 和 1–5 槽「去设置」；绑定 uTools 全局功能 `打开 Action 执行工作台` / `Codex Action 槽 N`。卡内 `Ctrl+Shift+1…5` 也只派发同一 Controller 命令
- **多 Environment：** Runner 左树可精确选择 Environment/Action，并由 Host 记住选择。目标项目从未选择过时，五槽才默认第一个 Environment；已有选择跨项目、已失效或缺少同序号 Action 时会拒绝执行并提示修复，不会静默回退。展开 Float 不提供 picker
- **项目 Node（macOS）：** 默认自动读取项目 `.nvmrc` / `.node-version`，再尝试 NVM default、其它本地 NVM 和受控系统 Node；也可在 Runner 为项目手动选择已验证候选。显式版本未安装时会拒绝执行并提示，不会静默换版本、source shell 或自动下载安装
- **Setup：** 不进入可执行命令，不会执行
- **命令边界：** 只接受不带任何 flag/额外参数的 `pnpm/npm/yarn/bun run build|serve`、`vite build|serve` 或 `git push`；TOML 必须写裸整数 `version = 1`。若 Runner 提示 Action Host 版本过旧，请正常重载插件后再执行
- **Serve：** 由 Host 管理长驻会话；重新执行时先 SIGTERM、等待真实退出，再重新读取配置和运行时。停止不会自动升级 SIGKILL
- **Git Push：** 外部写入，需 30 秒内再次确认；确认只对当前项目/worktree、Environment、Action 与当前配置有效
- **隐藏与退出：** 普通隐藏插件或 Runner 不会停止正在运行的 Action；真正结束插件进程时，未结束记录会先保存为 interrupted，再使用非强制终止。Windows 会尝试停止该 PID 的进程树，但不会使用强制 `/F`
- 界面不展示路径、命令原文、PID、环境变量或未脱敏输出；执行历史只保存安全投影，保留上限为 30 天、200 次、100 MB
- 默认项目在主窗口 Codex → **任务** 中配置；选「不配置」时使用置顶/最近项目回退

## 任务行为（用户可见）

- **动态：** 展示近期（按最新 Turn 活动，默认 24 小时内）的非隐藏任务与待输入等状态分段；可在 Codex → **任务** → **动态时间筛选（小时）** 修改范围，置顶任务排在分段内靠前
- **刷新周期：** Codex → **运行** → **额度刷新（秒）** 默认 300 秒；Codex → **任务** → **完整校对频率（秒）** 默认 15 秒。两者都可输入 `0–86400` 的整数，`0` 表示仅手动。完整校对只兜底发现漏事件，不会把已知待输入、开始或完成事件强制等到该周期。
- **待输入：** 含普通问题、审批和需你确认的 Plan 等；角标可直达第一条。实时 Desktop 请求优先；原请求 owner 已结束而 Desktop 无法重放时，EyPc 只会用受限读取确认的未回答输入或最新待实施 Plan 恢复该状态，不会把普通连接器提示当成待输入。全局功能「打开 Codex 待输入任务」优先打开真实待输入；若当前没有待输入，则按 EyPc 本地置顶顺序打开第一条可打开的本地置顶对话（含已完成等状态；不含 Codex 原生置顶）。该回退只影响快捷键目标，**不计入**待输入角标 / `inputRequired` 计数，也不同于「上一个 / 下一个」末层的非终止本地置顶兜底。
- **已完成未读：** 打开第一条任务；插件确认 Deep Link 打开成功后会立即把当前任务标为本会话已读，打开失败不变。该确认不写 Codex 原生状态，后续新 Turn 完成仍会重新未读；隐藏或恢复不改变未读
- **已停止：** 单独中性状态，不计入进行中角标，也不能归档
- **状态时机：** 全新任务仍会先安全登记项目与匿名身份；若事件到达时完整列表暂时还没出现它，Preload 会按该脏任务精确读取一次，并且只有项目、最新 Turn 与匿名动作门禁全部通过才同时加入卡片和角标，不会先做一个假数字。首次读取未命中时，仍为 live active 的未登记状态会留在 Preload 等真实列表追上；任务偶尔从完整清单暂缺时，既有匿名活动映射会在同一数据源下短暂保留，避免隔离复查期间把仍在运行的任务误判为停止。原请求 owner 消失后，安全恢复出的有限输入决定会携带独立来源进入同一状态包；普通连接器的 active/waiting 提示仍保守为进行中。已在任务池中的任务收到完整新 Turn 时，旧恢复决定会先清除，进行中卡片与角标直接同步；完整且新鲜的完成 Turn 按同一 Turn 的状态版本直接切换，不会因服务端秒级完成时间与本机毫秒观测时间无法严格比较而丢失。精确完成事件即使暂时没附完整 Turn，也会先对这一条任务立即读取并短间隔复核，不再先做全量库存扫描；若期间出现更新的 active/Turn-started/等待事件，旧完成读取会失效。曾被中断的同一 Turn 恢复时即使沿用原开始时间、又漏掉中间进行中事件，最新明确 completed 仍会前进到已完成。Desktop 首次订阅若重放一个与最新 terminal Turn 冲突的 active，EyPc 会在短暂定向核验期间先保守显示进行中，只有状态 revision 未变化、没有更新的明确进行中证据且最终读取仍 terminal 才一次切换；失败/中断冲突只会降为无法确认，不会合成“空闲/已停止”。任何真实新 Turn、等待请求、活动更新或读取失败都会保留/恢复进行中；即使活动本身未变化，新出现的 Plan/权限等待也会立即进入待输入并覆盖旧完成证据。反向也一样：新到达的 App Server 进行中证据不会再被旧的 Desktop idle 活动记录、未读变化、重新订阅或完整扫描回放成“已停止”；只有真正后到的停止活动或明确 terminal 证据才能结束它
- **切换任务：** 在 Codex Desktop 中切换任务只会改变 Desktop 当前关注对象；EyPc 会继续续订仍在任务池中的上一任务，不会让已停止任务重新进入进行中角标。若切换恰好与上一任务完成同时发生，即使 Desktop 短暂回放旧 active，EyPc 也会对该任务做一次有界的最新 Turn 校对，用明确 completed 同步完成分段与角标；校对期间若收到更新的进行中证据，旧校对结果会失效。Side Chat 会校对实际子任务并把活动、待输入与未读聚合回父任务。仍在运行或读取失败时继续保守显示进行中。完全退出 Codex、归档或任务确实离库时，仍按对应权威边界清理
- **多分支与诊断：** 一个 Side Chat 结束时，如果主任务或另一个 Side Chat 仍在运行，父任务继续显示进行中，不会被单个分支的晚到终态改成已停止/已完成。「运行」中的“状态裁决”常驻只显示保护合计与周期数，聚焦或悬停信息按钮可查看五项匿名明细；只有计数确实变化时刷新，普通轮询不会重复播报，也不含任务 ID、名称、正文或路径
- **版本提示：** uTools 若仍保留旧版任务桥，EyPc 会保留当前可用的任务卡片与三个角标，在状态摘要中标记“状态已保留，建议重载”；额度仍可继续显示。任务卡片、分组、角标、ARIA、设置预览和前后任务 active 候选来自同一个 Controller 状态包，不会因版本不一致被不同界面分别清空。若旧 Controller 已经发布了空数据，正常重载后会重新读取
- **归档：** 仅在已完成证据明确时可用；项目级「归档已完成」会按批处理并保留个别失败结果
- **上一个 / 下一个 Codex 任务：** 按独占优先级循环：先处理普通待输入/待审批；这些任务清空后，才在已完成规划、等待实施确认的 Plan 之间逐项回绕；Plan 清空后才进入动态时间筛选范围内的非隐藏进行中。普通层都为空时回退到当前未停止的 EyPc 本地置顶任务。旧任务桥无法识别 Plan 时会保守地把它当普通待输入。两者只发起共享打开动作，不改隐藏/Tab 或 Desktop 原生状态；Host 确认打开成功后沿用上述会话期已读规则

列表不展示任务正文；预览与详情也只含隐私安全字段（名称、项目、状态与时间等），不含路径、原始 ID、正文。

## 数据与平台边界

- **额度、模型、任务清单：** 来自本机 Codex App Server 连接（只读库存为主）
- **实时待输入 / 进行中 / 完成未读细分：** 优先依赖 macOS 上 Codex Desktop 实时桥；桥无法重放旧请求时，只允许本机 Codex 会话中经过结构化、有界复核的未回答输入或待实施 Plan 恢复“待输入”。普通连接器状态、本地 UI 缓存、正文或时间推测都不能伪造 Input/进行中，未确认项会保守显示为进行中类
- **Windows：** 支持 CLI 发现与校验；Desktop 实时桥仍以 macOS 能力为准，Windows 上实时细分可能不可用
- 普通库存扫描对 Codex 全局状态文件保持只读；唯一写例外是你明确确认的原生项目移除事务
- Easy Agent 尚未实现；当前为 App Server +（macOS）Desktop 桥的过渡方案

## 常用配置步骤

1. 确认功能已启用；打开 Codex Tab 查看「运行」诊断。
2. 在「快捷方式」为常用全局动作到 uTools 里绑定系统快捷键。
3. 在「任务」按需修改动态时间筛选和完整校对秒数；在「运行」修改额度刷新秒数。两个刷新周期填 `0` 都表示仅手动。
4. 在「水球 / 卡片」调整外观，预览与桌面悬浮共用同一套渲染逻辑。
5. 显示悬浮球后，用角标或展开卡片处理待输入与未读；需要时用上一个/下一个任务循环。
6. 如需项目 Action，在「任务」配置默认项目或置顶常用项目，打开 Action Runner 检查项目 Node 并选择需要的 Environment，再通过 Runner 或五个全局功能执行（以该项目 TOML 为准）；若 Runner 提示目标或版本需修复，先处理提示。展开 Float 不显示 Action 卡槽。

“进行中离开稳定窗”已取消：普通快照、完整完成通知、缓存结果和 active 退出后的定向核验，只要通过同一 Turn revision/status 门禁都会立即同步。旧的 0.5–3 秒保存值已不进入当前运行设置，下次正常保存时会自然淘汰。已接受的完成同时关闭本次活动周期，后续相同快照不会将它反判回进行中。首次 active snapshot 冲突核验、完整清单校对和任务缺行保护仍保留。

插件内 Codex Tab 另有 `Ctrl+T`（默认）在当前高亮会话或项目中新建会话（受 Tab/输入层约束）。

## 风险与边界

- 不向界面、日志、可同步存储暴露原始会话 ID、路径、Token、正文。
- 破坏性操作（如归档、项目移除、Git Push）需要确认；失败不会乐观删行。
- Action 是 EyPc 等价执行，不会调用不存在的 Codex 原生 Action API。
- 动作后隐藏插件时，不会为了切 Tab 而清掉正在进行的循环所需状态（实现已避免错误切 Tab 导致别名失效）。

## 与其它功能的关系

功能总开关在 **设置 → 功能开关**。通用快速跳转在 Codex 子窗有本地变体；主插件 `F` 跳转习惯见 **设置** 说明。

## 接入 Claude Code（可选）

Codex 与 Claude Code 是两个彼此独立的来源，可各自开关，也可同时开启共享同一个水球。**默认只开启 Codex**，此时插件完全不读取任何 Claude 数据，界面与只有 Codex 时逐字一致。

开启后：

- **任务汇总按状态而非来源**：待输入、进行中、已完成未读的角标数字是两边合计；任务列表顺序也不按来源分组，只在每行下方加一个来源标记
- **前后任务循环按来源分组**：在同一状态层内先走完 Codex 的任务再进入 Claude 的任务，组的先后固定，因此连续按「下一个」不会来回跳
- **跳转各走各的方式**：Codex 仍用原有的深链打开；Claude 会聚焦承载该会话的终端窗口，聚焦不到时在新终端里 `claude --resume` 恢复会话
- **已读由插件自己维护**：Claude 没有原生已读状态，只有确认聚焦成功才会把「已完成未读」标记为已读

### 事件钩子

要让 Claude 任务状态实时更新，需要在「运行」分区的 **接入来源** 里点一次 **注册事件钩子**。这是插件唯一一次写入你的 Claude 安装：

- 写入 `~/.claude/settings.json` 的条目都带 EyPc 标记，**你已有的钩子和设置原样保留**
- 如果你已经配置过状态栏，插件的包装脚本会**继续调用你原来的状态栏**，显示不受影响
- 随时可以点 **移除钩子** 干净卸载，你原来的状态栏会被还原
- 生成的脚本只记录会话 id、事件类型、时间、工作目录和进程号，**不记录任何对话正文、工具参数或回复内容**；凭证只探测存在性，从不读取

未注册钩子时，任务状态仍可从会话记录冷读出来，但不会实时变化。额度读数的常规来源是状态栏包装脚本，它只在 Claude Code 渲染时更新；一次读数都还没有时，插件会自动补读一次，见下。

找不到 `claude` 可执行文件不影响任务状态与额度——它只用于从卡片跳回会话。

### 额度从哪来

状态栏包装脚本是常规来源，它由 Claude Code 主动把官方额度对象交给我们，**不需要任何凭证**——代价是它只在 Claude Code 渲染时执行。这留下两段不同的空白，插件对它们的处理也不同：

**一次读数都没有（冷启动）**：额度区会一直空着，水球球心也没有可显示的数字。这种情况下插件会**自动**用账号用量接口补读一次，不需要你开任何开关，也不需要你先跑一次 Claude Code。这条路自带上限：整个插件进程内最多尝试 3 次，且最短 5 分钟一次；一旦拿到任何读数就不再触发。

**已有读数、但正在变旧（空闲漂移）**：这不是空白，只是不够新，所以保持**默认关闭**的独立开关（「运行」分区 → 空闲时持续补充读取额度）。开启后读数明显过期时会继续补读。

两条路走同一个接口，代价也相同：需要读取你的登录凭证（macOS 上会弹出钥匙串授权），并且调用的是一个 Anthropic 未公开文档的接口。凭证只在请求那一刻使用，不落盘、不进日志、不出现在任何返回值里；接口失败、变更或撤销时只保留上次读数，不会报错也不会影响任务状态。区别只在**频率**：冷启动最多 3 次然后彻底停手，空闲刷新则是长期周期性的——这正是后者仍然要你显式同意的原因。
